外部第三方 API 可以增强应用的功能，帮你实现原本难以想象的效果。本文将介绍 API 是什么、Rork 上已经提供了哪些 API，以及如何快速添加自定义 API。

<div id="so-youve-built-an-awesome-app-on-rork">
  ## 你已经用 Rork 做出了一款很棒的应用……
</div>

但现在你想更上一层楼。也许你的用户想要某个新功能，而它需要更复杂的工具支持。比如，用 Rork 做的照片应用可能想在用户拍照时加上 AI 滤镜，音乐发现类应用可能想加入从歌曲录音中识别曲风的能力。无论你在 Rork 上做什么，都可以不断迭代和打磨。这正是**外部 API**与 Rork 内置的顶尖应用构建器的强大之处。

<div id="what-is-an-api">
  ### 什么是 API？
</div>

最简单地说，API 可以看作一份**合约**。合约规定了双方共同认可的具体条款。设想这两方分别是你的应用和另一个应用。同理，API 相当于在说：“如果你的应用向我提供数据 A，这家公司就承诺从他们的服务中返回数据 B。”

> 举个例子，你可能正在 Rork 上开发一款应用，帮助用户根据饮食偏好找到附近最好的餐厅。要获取附近的餐厅列表，你就得找一个类似 Google Maps API 的接口。在应用中，你先获取用户的位置 (Rork 可以轻松做到) ，再把这些数据发送给 Google Maps API (具体做法参见文档后续内容) ，作为回报，这份合约承诺返回给你一份餐厅列表。

开发者依赖这份合约保持不变，因为任何变动都可能导致应用出错。这也正是 API 需要配备文档和清晰结构 (schema) 说明的原因。

<div id="what-is-an-external-or-third-party-api">
  ### 什么是外部 API 或第三方 API？
</div>

要回答这个问题，我们先来看看内部 API 是什么。API 是双方之间的一份约定，而这种约定同样可以存在于内部！举个例子，当你向 Rork 提交一段提示词时，我们会调用自己在 backend 上构建的内部 API 来处理你的提示词并构建你的应用。这就是一个无需第三方参与的内部 API。

<div id="how-to-find-the-right-api-for-your-project">
  ### 如何为你的 project 找到合适的 API
</div>

如果是 AI 图像、视频、音频或 3D 生成，你完全不需要外部 API。Rork 会为你生成这些媒体内容，[图像、视频、音频和 3D 模型](/zh/features/assets) 中说明了如何提出需求。如果你要做的是其他功能，请继续往下读。

1. **确定应用要做的功能改动**
   也就是你希望应用相比当前状态发生的那一项改动。如果你说不清自己想要什么改动，就很难找到能解决它的 API。改动要尽量简单，否则可能通不过下一步的可行性验证。你也可以换个角度思考：你目前有哪些数据源 (用户位置、饮食偏好、拍摄的照片等) ，以及你想用这些数据做什么。

2. **做一次可行性验证**
   在 ChatGPT、Gemini 或任何其他支持联网搜索的大语言模型中，你可以用下面这段提示词来搜索 API：

   > 我正在做一个移动应用。它是 (简要描述你的移动应用) 。目前的功能是 (说明现有功能以及你拥有的数据源) 。我想添加/改成 (你在第 1 步中确定的新改动) 。请联网搜索，找出可靠且维护良好、我可以接入来实现这一点的 API。

   这样就能判断你的需求是否可行。所有开发者在使用一个新 API 之前都会做这项重要检查。否则，你可能用上并不适合自己使用场景的东西，或者因为它疏于维护而突然出问题。

3. **注册该 API、找到文档并生成凭据**
   大多数 API 都要求你注册账号，并创建某种身份验证凭据。具体做法因 API 而异，但通常是一个 API 密钥和/或某种身份验证请求。手动处理容易让人摸不着头脑，所以可以在同一个 ChatGPT 会话中，请它帮你弄清楚究竟需要哪些凭据。只需附上文档链接并提问：

   > 使用这个 API 我需要哪些密钥/凭据，我该如何生成/找到它们？我之后要把它们添加到我的 Rork 应用中。另外请生成一份该 API 的使用说明，让我可以传给 Rork AI 编辑器，用来修改我的移动应用。

4. **现在可以把这些信息交给 Rork，开始构建你的新功能了！**
   关于如何把这些信息传入 Rork 并实现新改动，请参阅下一节。

<div id="how-to-tell-rork-to-use-external-apis">
  ### 如何让 Rork 使用外部 API
</div>

1. 我们来整理一组简单的说明，把它们发给 Rork 编辑器来实现所需功能：
   1. **我们想把这个 (应用当前的功能) 改成这个 (应用的新功能) 。**
   2. **为此，我们要使用外部 API (外部 API 的名称) 。**
   3. **以下是我们需要的完整文档： (复制文档，或粘贴你在上一部分第 3 步中让 ChatGPT 生成的说明)&#x20;**
   4. **以下是使用该 API 所需的凭据： (粘贴你在上一部分第 3 步中找到的凭据)&#x20;**
2. 把填写好的这 4 句话发给 Rork 编辑器。Rork 会智能判断，找出把该 API 接入你的代码库和应用的最佳方式。
3. 在应用中测试新的改动，如果有问题就继续迭代。
4. **排查技巧：**
   1. 如果功能调用失败，可以把报错发给 Rork 让它修复。如果没有显示明确的报错，就让 Rork：**记录对该 API 的调用日志，以便我们调试失败的原因**。
   2. 如果功能可以运行，但返回的数据不符合预期或有缺失，就让 Rork：**记录该 API 调用返回的数据，以便我们在应用中正确使用这些数据**
5. 恭喜！你刚刚提升了应用的价值，还接入了一个外部 API！欢迎在我们的 Discord 上分享你正在打造的作品* (链接位于文档左上方) *。我们很想看看你是怎么使用外部 API 的！
