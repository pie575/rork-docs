---
title: "API 密钥与环境变量"
---

把 API 密钥存放在 Rork 项目中，而不是直接粘贴到代码里。本页介绍 Secrets 编辑器、哪些变量会下发到手机端，以及如何让私钥始终保持私密。

大多数实用的 app 都需要密钥：天气 API、邮件发送服务、支付服务商、模型服务商。这些密钥应当放在项目的 **Secrets** 中，而不是写进代码，也不要发在聊天消息里。

<div id="where-secrets-live">
  ## 密钥存放在哪里
</div>

在项目中打开 **More → Secrets**。

<Frame>
  <img alt="Rork 的 Secrets 面板，包含一行 RESEND_API_KEY、隐藏的值、Server-side only 标签、Add Variable 按钮，以及 Bulk Edit 和 Save 按钮" />
</Frame>

<Steps>
  <Step title="点击 Add Variable">
    会出现新的一行，包含 **Key** 和 **Value**。
  </Step>

  <Step title="用大写字母加下划线的形式填写名称">
    如 `RESEND_API_KEY`、`STRIPE_SECRET_KEY`、`OPENWEATHER_API_KEY`。请使用服务商文档中给出的确切名称。
  </Step>

  <Step title="粘贴值">
    Rork 会立即将其隐藏。需要核对时，点击眼睛按钮即可查看。
  </Step>

  <Step title="点击 Save">
    Rork 会保存该变量，并重新构建应用中用到它的部分。
  </Step>
</Steps>

如果要一次添加多个，用 **Bulk Edit** 更快：按 `KEY=value` 的格式，每行粘贴一个变量。

<div id="how-far-a-variable-travels">
  ## 变量能传到多远
</div>

每个键下方的标签是本页的重点，它告诉你谁能读取这个值。

| 标签         | 值会传到哪里               |
| ---------- | -------------------- |
| **仅服务端**   | 只留在服务器上，用户永远读不到      |
| **构建时可用**  | 在构建应用时被写入应用中         |
| **所有用户可见** | 随应用一起分发，任何安装应用的人都能读取 |

决定归属的是变量名。名称以 `EXPO_PUBLIC_` 开头的变量会被发送到应用本身，其余的一律留在服务端。编辑器在底部也重申了这条规则：&quot;Prefix with `EXPO_PUBLIC_` to make a variable available on the client-side&quot;。

<Warning>
  切勿给密钥取以 `EXPO_PUBLIC_` 开头的名称，也切勿把密钥粘贴到应用代码里。凡是随应用一起分发的内容都能被提取出来，这意味着你账户上的密钥会泄露、被陌生人使用，账单却算在你头上。私钥应当放在**仅服务端**变量中，由服务端函数调用。
</Warning>

两个例子能把界限说清楚：

* `EXPO_PUBLIC_SUPABASE_URL` 作为公开值没有问题。它只是一个地址，而且有数据库规则保护。
* `STRIPE_SECRET_KEY` 必须设为**仅服务端**。它能动钱。

如果你的功能需要私钥，就让 Rork 帮你做一个服务端函数：

```
用服务端函数发送确认邮件，这样 Resend 密钥就不会外泄
```

有些条目会标记为 **由 Rork 管理** 或 **由 Supabase 集成管理**。这些值由 Rork 自行写入并轮换，请勿改动。

<div id="when-rork-asks-you-for-a-key">
  ## 当 Rork 向你索取密钥时
</div>

通常你根本不用打开 Secrets 编辑器。当构建需要某个密钥时，Rork 会暂停并在聊天中向你询问：每个密钥对应一个输入框，并附有简短说明，介绍该密钥的用途。粘贴对应的值后点击 **Save &amp; Continue**，构建便会从中断处继续。

如果 Rork 已经知道这些值 (例如在完成某项集成之后) ，卡片则只会请你确认：**Yes, set them**。

<div id="who-can-see-your-keys">
  ## 谁能看到你的密钥
</div>

| 角色  | 密钥          |
| --- | ----------- |
| 所有者 | 可读取和编辑      |
| 编辑者 | 可读取和编辑      |
| 查看者 | 可看到面板，但无法编辑 |

也就是说，项目中的编辑者可以读取你的密钥，因此邀请编辑者时请慎重。参见[共享项目并协作](/zh/collaborate/share-a-project)。

克隆项目时会一并带上你的变量，但由 Rork 自行管理的密钥除外——这些密钥会为副本重新生成。

<div id="rotate-a-key-you-leaked">
  ## 轮换已泄露的密钥
</div>

如果密钥出现在了公开的地方，仅仅在 Rork 中修改是不够的。请按以下顺序操作：

<Steps>
  <Step title="在服务商处吊销密钥">
    在服务商自己的控制台中删除或轮换该密钥。这一步才能真正让密钥失效。
  </Step>

  <Step title="创建新密钥">
    复制新的密钥值。
  </Step>

  <Step title="在 Rork 中更新变量">
    保持键名不变，填入新的值，然后点击 **Save**。
  </Step>

  <Step title="排查泄露位置">
    如果密钥出现在你的代码中，让 Rork 将其删除，改为从变量中读取该值。
  </Step>
</Steps>

<div id="faq">
  ## 常见问题
</div>

<AccordionGroup>
  <Accordion title="我应该把 API 密钥粘贴到聊天里吗？">
    建议使用 Secrets 编辑器，或者 Rork 在需要密钥时弹出的卡片。这两种方式都能让密钥不出现在对话中。
  </Accordion>

  <Accordion title="密钥会同步到 GitHub 吗？">
    不会。它们保存在项目中，而不在代码里，因此不会被提交。如果你自己运行代码，需要在对应环境中重新设置一遍。参见[如何将项目与 GitHub 同步](/zh/tutorials/how-to-connect-github)。
  </Accordion>

  <Accordion title="密钥是按项目还是按账户区分的？">
    按项目。同时包含 iPhone app 和 web app 的项目会共用同一组变量。
  </Accordion>

  <Accordion title="我添加了变量，但 app 仍然读取不到。">
    先重新加载预览。如果是原生 app，变量值是在构建时写入的，因此需要重新构建。如果变量名缺少 `EXPO_PUBLIC_` 前缀，app 按设计就无法读取，这类调用应放在服务端。
  </Accordion>

  <Accordion title="在 app 中使用 AI 需要自己的 OpenAI 密钥吗？">
    不一定。Rork Cloud 会为你的 app 提供模型，无需自备服务商密钥。参见[什么是 Rork Cloud](/zh/backend/rork-cloud)。
  </Accordion>

  <Accordion title="Supabase 的密钥放在哪里？">
    连接 Supabase 时会自动帮你设置好，并标记为托管状态。参见[如何为 Rork 添加 Supabase backend](/zh/backend/supabase)。
  </Accordion>
</AccordionGroup>
