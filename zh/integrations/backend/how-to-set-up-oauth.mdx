---
title: "如何为你的 Rork 应用添加 Apple/Google 登录"
---

本指南将带你逐步了解如何为 Rork 应用添加社交登录 (Apple/Google)

<div id="prerequisites">
  ## 前置条件
</div>

你需要准备：

* 一个 **Supabase 项目**
* 你的 **Supabase Project URL** 和 **Anon/Public key** (用于连接 Rork ↔ Supabase) 
* 以下访问权限：
  * **Google Cloud Console** (用于获取 Google OAuth Client ID 和 Secret) 
  * **Apple Developer** 账号 (用于配置 Sign in with Apple)

<div id="step-1-connect-rork-to-supabase">
  ## 步骤 1 – 将 Rork 连接到 Supabase
</div>

1. 在 Supabase 中，复制：
   * **Project URL** (项目 URL) 
   * **Public anon key** (公开匿名密钥) 
2. 在 Rork 中，输入类似这样的提示词：
   * **“Connect to Supabase”**
   * 然后按提示提供 Project URL 和 anon key

这是配置登录提供商前必须完成的第一步。

<div id="step-2-enable-google-sign-in-in-supabase">
  ## 第 2 步 – 在 Supabase 中启用 Google 登录
</div>

1. 前往 **Supabase → Authentication → Sign-in / Providers**
2. 找到 **Google** 并将其启用

<div id="create-google-oauth-credentials-client-id-secret">
  ### 创建 Google OAuth 凭据 (Client ID + Secret) 
</div>

1. 前往 **Google Cloud Console**
2. 创建一个**新的 OAuth 客户端**
3. 选择“**Web application**”
4. 创建完成后，复制：
   * **Client ID**
   * **Client Secret**

<div id="paste-credentials-into-supabase-add-redirect-url">
  ### 将凭据粘贴到 Supabase 并添加重定向 URL
</div>

1. 将 **Client ID** 和 **Client Secret** 粘贴到 Supabase 的 Google 提供商设置中
2. 从 Supabase 复制 **Callback/Redirect URL**
3. 回到 Google Cloud Console (编辑你的 OAuth 客户端) ：
   * 将该 URL 添加到 **Authorized redirect URIs。** 步骤 3 — 在 Rork 中添加登录页面 (带 Google 回调) 

在 Rork 中输入提示词：

* “在用户进入应用前，先添加一个登录页面。”
* 然后用类似下面的标签附上你的回调 URL：

**示例提示词格式：**

* `Google: <SUPABASE_CALLBACK_URL>`

这样能帮助 Rork 正确接入登录功能。

<div id="step-4-enable-apple-sign-in-in-supabase-apple-developer">
  ## 第 4 步 —— 在 Supabase 和 Apple Developer 中启用 Apple 登录
</div>

1. 在 **Supabase → Auth providers** 中启用 **Apple**

<div id="create-an-apple-key-sign-in-with-apple">
  ### 创建 Apple 密钥 (Sign in with Apple) 
</div>

在 **Apple Developer** 中：

1. 进入 **Identifiers** (这里主要围绕你的 App 和 Sign in with Apple 功能进行配置) 
2. 进入 **Keys**
3. 点击 **Add Key**
4. 启用并配置 **Sign in with Apple**
5. 选择你的 App，保存并继续
6. **Register** (注册) 该密钥，然后**下载并妥善保存**

<div id="ensure-your-app-id-has-sign-in-with-apple-enabled">
  ### 确认你的 App ID 已启用“Sign in with Apple”
</div>

继续在 Apple Developer 中操作：

1. 前往 **Identifiers → 你的 App ID**
2. 启用 **Sign in with Apple**
3. 保存并确认功能 (Capability) 变更

<div id="add-bundle-id-to-supabase-apple-provider">
  ### 将 Bundle ID 添加到 Supabase 的 Apple Provider
</div>

1. 在 Apple Developer 中，打开应用信息页，复制 **Bundle ID**
2. 在 **Supabase → Apple provider** 中，将该 Bundle ID 粘贴到 **Client ID** 字段
3. 保存

随后，再从 Supabase 复制 **Apple 回调 URL**。

<div id="step-5-final-rork-prompt-add-google-apple-oauth">
  ## 第 5 步 —— 最终 Rork 提示词：添加 Google + Apple OAuth
</div>

两个登录提供商都已在 Supabase 中配置完毕，现在可以让 Rork 把它们添加到应用中。

可以使用类似这样的提示词：

* “使用 Supabase 添加 Google 和 Apple OAuth。”
* 在提示词中附上两个回调 URL (Google + Apple)

<div id="step-6-test-fix-common-issues">
  ## 第 6 步 — 测试并修复常见问题
</div>

<div id="issue-a-google-opens-safari-and-fails-to-connect">
  ### 问题 A：Google 打开 Safari 后无法连接
</div>

如果你看到类似这样的提示：

* “Safari 打不开该网页，因为无法连接到服务器……”

教程中给出的解决方法是：

* 在 Supabase Auth 设置中开启 **new users to sign up** (允许新用户注册) 

开启注册后，Google 登录应该就能顺利完成，并将用户带回应用内。

<div id="issue-b-apple-opens-safari-and-says-missing-oauth-secret">
  ### 问题 B：Apple 打开 Safari 并提示“missing OAuth secret”
</div>

如果 Apple 登录跳转到了浏览器，并且出现以下提示：

* “missing OAuth secret”

这通常是因为该流程走的是基于网页的 OAuth 路径，而不是原生的 Sign in with Apple。

**修复方法 (推荐) ：** 让 Rork 把 Apple 登录改为**仅使用原生方式**重新实现。

<div id="prompt-you-can-use">
  ### 可以使用的提示词
</div>

> “把 Apple 登录改为仅使用原生方式，不要通过网页浏览器进行 Apple 登录。”

完成后，Apple 登录应显示为 **原生 Apple 界面** (而非 Safari) 。
