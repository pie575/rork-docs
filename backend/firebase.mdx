This guide helps you create a backend with Firebase for your Rork project, including user authentication and custom database schemas.

<Warning>
  **Most apps do not need a backend.** This is complex work and it can break a working project. Read [Do you need a backend?](/backend/index) first. If you do need one and would rather not run it yourself, [Rork Cloud](/backend/rork-cloud) gives you a database and server functions inside Rork with no second account.
</Warning>

## Create a Firebase account

1. Go to [Firebase](https://console.firebase.google.com/) and log in with your Google account.
2. Create a new Firebase project. You can skip the Gemini AI assistance and Analytics parts for now.
3. After you have a Firebase project, register your app within that project.

**Registering your app:** Look for the **Add App** button and choose the platform that matches your app: **iOS** for an iPhone app, **Android** for an Android app, **Web** for a web app. Firebase then gives you a config:

- iOS: a `GoogleService-Info.plist` file
- Android: a `google-services.json` file
- Web: a `firebaseConfig` object

## Collect your config

After registering your app, Firebase shows you its SDK setup screen with the `firebaseConfig` object. Copy the entire second code block, then go to the Rork editor and type:

```text
Please install firebase package and setup the init config.
Please also setup Firebase Auth and Firebase Database:
{PASTE YOUR ACTUAL COPIED CONFIG FROM ABOVE HERE}
```

## Create the backend data schema

You need to figure out the data schema for your application. Firebase uses NoSQL (Firestore) instead of tables, which means:

- You create **collections** (like tables)
- Each user or post is a **document**
- A document contains **fields**
- You can have **subcollections** nested inside documents

Ask Rork to help you design it:

```text
Please list out all of the data schema collections required for our application to work.
I will be using this list to create my Firestore collections and security rules.
```

### Create your Firestore database

1. In your Firebase project, click **Firestore Database** in the left panel.
2. Create a database and pick a region closest to your users. You cannot change this later.
3. Go to the **Rules** tab and paste in the security rules Rork gave you.

Unlike Supabase, Firestore builds collections automatically when your app writes to them, so there is no need to create them manually first.

## Set up authentication

<Steps>
  <Step title="Enable email and password auth">
    In your Firebase dashboard, go to **Authentication** → **Get Started** → **Sign-in method** → enable **Email/Password**.
  </Step>
  <Step title="Optionally add OAuth providers">
    Enable Google, Apple, or phone number sign-in if you want them. These are the most popular auth methods for consumer apps.
  </Step>
  <Step title="Integrate auth into Rork">
    In your Rork editor, ask:

    ```text
    Please integrate Firebase Authentication into this project.
    I want email+password sign up, sign in, sign out, and proper session handling.
    Use:
    - createUserWithEmailAndPassword
    - signInWithEmailAndPassword
    - onAuthStateChanged for sessions
    After sign up, please also create a user document in Firestore inside the "users" collection.
    ```

    Rork generates a signup function, a login function, an auth state listener, the code to create the initial user document, and navigation updates for logged-in vs logged-out users.
  </Step>
</Steps>

## Ask Rork to apply your schema and build your functions

Now that authentication is working and your security rules are in place, give Rork your app's schema so it can generate all the backend functionality your project needs.

```text
I have added the Firebase Security Rules.
Please apply the schema from before that you stated to the project and generate all
helper functions required for it, including create, read, update,
delete, queries, and any subcollection or media upload functionality needed.
```

Rork will build:

- Firestore collection/document structures
- Create, read, update, and delete functions
- Queries (feed, user posts, lists, etc.)
- Subcollection logic (comments, likes, followers, etc.)
- Firebase Storage upload helpers for images, audio, and video
- Fully typed helper functions your app can call

If it misses a relationship or a field, update your schema and re-run the request.

## Test your database

Once everything is connected, test your app and confirm that actions update the Firestore collections. Changes should persist when you restart the app. Congratulations on building a backend!
