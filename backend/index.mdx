Rork builds the **frontend** of your app: the screens people see and touch, on iPhone, on Android, and on the web. A **backend** is the part they never see. It stores data, keeps accounts, and enforces rules. Not every app needs one.

By the end of this page you will know which category your idea falls into, and what to do next.

## 1. Apps that need no backend

### Local-only apps (everything stays on the device)

These are apps that store all their data on the user's phone. No sync needed. No logins required. No sharing.

Examples: todo lists, notes apps, journals, habit trackers, mood logs, calculators, timers, unit converters, offline flashcards, photo filters, utility widgets.

Rork can build and store the data for all of these with no backend at all, using the device's own storage.

```text
Make sure the data is stored on the device and survives a restart
```

### Tools with temporary or non-persistent data

If nothing needs to persist after the app closes, no backend is needed. Examples: playground apps (drawing, sandbox), local mini-games, one-off AI generators that do not keep the result.

### AI apps that only call an external API

If your app just sends a prompt to GPT and returns the response, you do not need a backend. You are just making requests to OpenAI or another AI provider.

A backend becomes useful only when you want user history, personalization, or usage tracking. This applies to any external API: as long as you do not need to store the data, you can use any API without a backend.

## 2. Apps that always need a backend

### Apps with accounts or login

If the user "has an account," you need authentication, the ability to restore their data, and sync across devices. Examples: social apps, productivity apps with cloud sync, finance apps, any multi-device workflow.

### Apps that sync across devices

A user writes a note on their phone and expects it on their laptop. That requires a database, cloud sync, and persistent storage.

### Apps with sharing, collaboration, or multiplayer

If more than one person can see, edit, or comment on the same thing: messaging, friends lists, comments, posts, social feeds, real-time collaboration, dating apps. All of this needs a backend.

### Apps that store files

If your app handles images, videos, PDFs, or audio recordings that must persist across devices, you need a backend.

### Apps with security or access rules

Client-only apps cannot enforce rules. If your app needs blocking, moderation, rate limiting, or anti-spam, a backend is required.

## 3. Gray-zone apps (optional backend)

### Local-first apps with optional sync later

Some apps work great without a backend, then add cloud features later. You can ship v1 with no backend and add sync when you grow. Examples: journal that adds cloud backup, notes app that adds multi-device sync.

### AI apps with memory or personalization

You can choose local-only memory (no backend) or cloud memory across devices (backend). Your v1 can be simple with local storage; once you have users, you can move to a more advanced system.
