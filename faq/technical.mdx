Frequently Asked Questions about technical building with Rork

## Are Rork apps actually native iOS/Android apps? Or is it just web apps?

They are real native apps. Rork writes **SwiftUI** for iPhone and **Kotlin + Compose** for Android: the same languages Apple and Google use for their own apps. New projects are Swift, Kotlin, or web. They are not a website wrapped in a web view.

Native code is designed for performance, precision, and polish. It delivers smooth animations, responsive interfaces, and immediate access to the latest platform features, from widgets and Live Activities on iOS to Material You theming and background work on Android.

Rork also builds **web apps** in React when the product belongs in a browser. Those are web apps by design, and you publish them to your own address instead of an app store. See [iPhone, Android, or web: what's the difference](/swift-vs-react-native/whats-the-difference).

### Can I use Rork to build production-ready apps?

Yes. Rork supports apps ranging from 0 users to 100k users.

### Does it work on iOS and Android?

Yes. An iPhone app and an Android app are two separate native apps, and one Rork project can hold both. Ask for the second platform at any time and the agent rebuilds your screens and flows in it. See [Convert your app between iOS, Android, and web](/import/convert-between-platforms).

### I have an older Expo (React Native) project. Does it still work?

Yes. Rork no longer creates Expo projects, but the ones you already have keep working: you can build them, publish them, and export the code to GitHub. If you want Swift or Kotlin instead, ask the agent to add a native iPhone or Android app to the project. See [What happened to Expo?](/expo).
