---
title: "Rork Web: создание и публикация веб-приложения"
---

Rork создаёт веб-приложения на Vite и React, показывает предпросмотр рядом с чатом и публикует их по вашему собственному адресу на rork.app. Подходит для сайта, дашборда, клиентского портала или административной панели.

<div>
  <img alt="Веб-проект в Rork: чат слева и готовый сайт Ember Roast в живом предпросмотре справа" />
</div>

<p>Один запрос, один проект: чат слева, работающий сайт справа.</p>

Веб-приложение Rork работает в браузере. Rork пишет его на **Vite и React**, показывает предпросмотр рядом с чатом и публикует по вашему собственному адресу на `rork.app`. Никакого магазина приложений, никакой проверки, никакой установки. Вы просто делитесь ссылкой, а люди открывают её на ноутбуке или телефоне.

Web — подходящая платформа для сайта, дашборда, клиентского портала, административной панели или SaaS-продукта. И это самый быстрый способ показать людям результат уже сегодня. Посмотрите примеры на [странице Rork Web](https://rork.com/web).

<div id="start-a-web-app">
  ## Создание web app
</div>

Выберите платформу до отправки первого сообщения. На [rork.com](https://rork.com) откройте список платформ под полем ввода и выберите **For web**. Затем опишите продукт, а не технологию.

<Frame>
  <img alt="Поле ввода Rork с запросом про кофейную обжарочную и выбранной платформой For web" />
</Frame>

Там прямо сказано: **другую платформу можно добавить позже**. Один project может одновременно содержать app для iPhone, app для Android и web app. См. [Перенос приложения между iOS, Android и web](/ru/import/convert-between-platforms).

<div id="answer-the-questions-about-the-look">
  ## Ответьте на вопросы об оформлении
</div>

Rork не приступает к написанию кода сразу. Сначала он задаёт несколько коротких вопросов об оформлении, причём каждый ответ — это картинка, а не слово. Свой вариант ответа можно ввести в поле **Other**.

<Frame>
  <img alt="Rork спрашивает, как в целом должен выглядеть сайт, и предлагает на выбор четыре варианта палитры" />
</Frame>

Ответьте на все три вопроса и нажмите **Submit**. Этот шаг можно пропустить, описав желаемое оформление прямо в первом запросе.

<div id="approve-the-design-then-build">
  ## Утвердите дизайн, затем запустите сборку
</div>

Дальше Rork отрисовывает экраны и показывает их в **Design mode**. Пока ничего не собрано, так что сейчас передумать проще всего. Попросите в чате другой экран или нажмите **Build**, чтобы превратить дизайн в работающий сайт.

<Frame>
  <img alt="Design mode с тремя предложенными экранами для Ember Roast и карточкой Review design с кнопками View Design и Build" />
</Frame>

<div id="work-in-the-project">
  ## Работа в проекте
</div>

В проекте слева находится чат, а справа — живой предпросмотр. Предпросмотр — это настоящее приложение, а не картинка, поэтому по нему можно кликать прямо в процессе работы.

Элементы управления над предпросмотром работают так:

| Элемент управления                  | Что он делает                                                                  |
| ----------------------------------- | ------------------------------------------------------------------------------ |
| **Сменить платформу предпросмотра** | Переключает предпросмотр между приложениями проекта и добавляет платформу.     |
| **Сменить размер предпросмотра**    | Циклически переключает предпросмотр между **Desktop**, **Tablet** и **Phone**. |
| **На главную**                      | Возвращает предпросмотр на первую страницу.                                    |
| **Перезагрузить предпросмотр**      | Загружает приложение заново после изменений.                                   |
| **Выбрать элемент для запроса**     | Укажите на часть страницы и напишите, что в ней нужно изменить.                |
| **Опубликовать**                    | Открывает панель публикации.                                                   |

<Tip>
  Вместо того чтобы описывать расположение словами, используйте **Выбрать элемент для запроса**. Укажите на элемент и напишите: «сделай эту кнопку темнее». Агент получит именно нужный элемент и меньше затронет всё вокруг.
</Tip>

<div id="check-the-phone-width">
  ## Проверьте ширину телефона
</div>

Web app должно одинаково хорошо работать и в браузере телефона, и на ноутбуке. Нажимайте **Switch preview size**, пока не появится значение **Phone**. Rork покажет сайт внутри рамки телефона, так что вы увидите те же страницы на той ширине, что и ваши посетители.

<Frame>
  <img alt="Сайт Ember Roast в режиме предпросмотра Phone, отрисованный внутри рамки телефона рядом с чатом" />
</Frame>

Затем попросите внести нужные правки:

```
На ширине телефона текст в hero-блоке перекрывает изображение. Расположи их друг под другом.
```

<div id="publish-to-the-web">
  ## Публикация в вебе
</div>

Откройте **Publish** и нажмите **Publish to web**. Rork соберёт app и разместит его по собственному адресу на `rork.app`.

<Frame>
  <img alt="Панель публикации Rork с адресом ember-roast-website.rork.app, статусом Site offline, неактивной строкой Add a custom domain и кнопкой Publish to web" />
</Frame>

Что показывает панель:

* **Адрес.** Rork подбирает его по названию project, например `ember-roast-website.rork.app`. Нажмите на карандаш, чтобы изменить поддомен.
* **Статус.** До первой публикации отображается **Site offline**.
* **Add a custom domain.** Эта строка остаётся неактивной до первой публикации. Панель прямо сообщает об этом: «Publish the project first to add a custom domain».

Публикация — это отдельный шаг, не связанный со сборкой. Изменения остаются в предпросмотре, пока вы не опубликуете их заново, а кнопка **Publish** подсвечивается, когда работающий сайт отстаёт от вашего project.

После первой публикации панель меняется: статус становится **Live**, отображается время выхода версии, а кнопка **Unpublish** снимает сайт с публикации.

<Frame>
  <img alt="Панель публикации с адресом rork.app, статусом Live, активной строкой Add a custom domain и кнопками Published и Unpublish" />
</Frame>

<div id="domains">
  ## Домены
</div>

Адрес вида `rork.app` вполне годится для тестирования, но настоящему продукту нужно настоящее имя. Домены настраиваются в двух местах, и полезно понимать, за что отвечает каждое из них:

* **Настройки аккаунта → Домены** — здесь домен добавляется в Rork. Вы покупаете его или подключаете свой собственный — по одному разу для каждого домена.
* **Панель публикации проекта** — здесь вы привязываете адрес к конкретному приложению. Это делается один раз для каждого проекта.

<div id="the-domains-list">
  ### Список доменов
</div>

Откройте меню аккаунта и перейдите в **Account settings → Domains**. Здесь перечислены все домены вашего аккаунта, а под каждым из них — его адреса.

<Frame>
  <img alt="Вкладка Domains в настройках аккаунта Rork: панель Add a domain и подключённый домен с двумя адресами со статусом Live" />
</Frame>

У каждого адреса свой статус. **Live** означает, что адрес обслуживает ваше приложение. Пока Rork настраивает адрес, отображается статус **Finishing, routing traffic to the app**. Кнопка **Add more subdomains** добавляет ещё один адрес на том же домене, а значок корзины удаляет домен целиком.

<div id="buy-a-new-domain-or-connect-one-you-own">
  ### Купите новый домен или подключите свой
</div>

Нажмите **Add domain**. Этот шаг Rork передаёт своему доменному партнёру — **Entri**, который выполнит техническую настройку за вас. На первом экране нужно выбрать один из двух вариантов:

<Frame>
  <img alt="Диалог Entri с заголовком Add a domain to Rork и вариантами Buy a new domain и Connect a domain" />
</Frame>

| Вариант              | Когда выбирать                                                         | Что произойдёт                                                                       |
| -------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| **Buy a new domain** | У вас ещё нет домена или вы хотите отдельный домен для этого продукта. | Вы подбираете имя и покупаете его прямо здесь. Домен сразу настроен на Rork.         |
| **Connect a domain** | Домен уже принадлежит вам — у любого регистратора.                     | Вы указываете домен, а Entri прописывает DNS-записи, которые направляют его на Rork. |

<Note>
  Покупка проходит через Entri, а не за счёт ваших кредитов Rork; домен оплачивается ежегодно, как и любая другая регистрация.
</Note>

В обоих случаях домен появится в списке выше. Прежде чем привязывать к нему проект, дождитесь, пока у адреса появится статус **Live**.

<div id="point-a-project-at-an-address">
  ### Привязка проекта к адресу
</div>

Домен добавлен в аккаунт, но пока по нему не отвечает ни одно приложение. Эта связь настраивается в проекте.

<Steps>
  <Step title="Опубликуйте проект хотя бы один раз">
    Пока вы этого не сделаете, строка с собственным доменом будет неактивна. До первой публикации в панели отображается сообщение «Publish the project first to add a custom domain».
  </Step>

  <Step title="Откройте Add a custom domain">
    В проекте откройте **Publish** и нажмите **Add a custom domain**.

    <Frame>
      <img alt="Диалог Connect a domain с выбором домена, двумя адресами с пометкой Connected to another project, кнопкой Add a subdomain и кнопками Cancel и Connect" />
    </Frame>
  </Step>

  <Step title="Выберите домен">
    Укажите его в поле **Domain**. В списке представлены домены, добавленные в ваш аккаунт.
  </Step>

  <Step title="Отметьте адреса">
    В разделе **Put your app on these addresses** отметьте, по каким адресам должен отвечать этот проект: голый домен, версия с `www` или оба варианта. Чтобы добавить адрес вида `app.example.com`, нажмите **Add a subdomain**.
  </Step>

  <Step title="Нажмите Connect">
    Кнопка **Connect** остаётся неактивной, пока не отмечен хотя бы один адрес.
  </Step>
</Steps>

Один адрес обслуживает один проект. Адрес, который уже используется другим проектом, помечается как **Connected to another project**, и отметить его нельзя. Если заняты все адреса домена, диалог сообщит об этом и предложит перейти к поддомену или к другому домену в разделе **Account Settings**.

<div id="add-a-web-app-to-a-project-you-already-have">
  ## Добавьте web app в уже существующий проект
</div>

У любого мобильного проекта может появиться веб-версия. Откройте **Project Settings → Add new app → Web**, воспользуйтесь переключателем платформ над превью или просто попросите:

```
Добавь веб-версию этого приложения
```

У каждого приложения свой код. Общими остаются чат и backend, если он у вас есть. Частый вариант разделения — мобильное приложение для клиентов и web app в качестве админ-панели.

<div id="what-a-web-app-cannot-do">
  ## Что web app не умеет
</div>

Web app работает в браузере, поэтому по-настоящему нативные возможности ему недоступны:

* Нет распространения через App Store или Google Play
* Нет виджетов на домашнем экране и экране блокировки, нет Live Activities и Dynamic Island
* Нет приложения для Apple Watch и интеграции с Apple Health
* Нет отслеживания в фоновом режиме, нет продвинутого отслеживания движений и активности тела
* Push-уведомления ограничены. На iPhone и iPad пользователю нужно сначала добавить сайт на домашний экран (на iOS 16.4 или новее), а затем выдать разрешение

Если вашему продукту нужно что-то из этого — создайте нативное приложение, а web app оставьте рядом с ним. См. [iPhone, Android или web: в чём разница](/ru/swift-vs-react-native/whats-the-difference).

<div id="faq">
  ## Частые вопросы
</div>

<AccordionGroup>
  <Accordion title="Какой код Rork пишет для веба?">
    Настоящий проект на Vite и React с TypeScript и стилями на Tailwind. Его можно выгрузить в GitHub и запустить где угодно. См. [Как подключить GitHub](/ru/tutorials/how-to-connect-github).
  </Accordion>

  <Accordion title="Можно ли пропустить вопросы и этап дизайна?">
    Да. Опишите желаемый внешний вид уже в первом запросе — тогда у агента будет меньше вопросов. В **Design mode** также можно сразу нажать **Build**.
  </Accordion>

  <Accordion title="Может ли у web app быть backend?">
    Да. Используйте [Rork Cloud](/ru/backend/rork-cloud) для backend внутри Rork либо подключите [Supabase](/ru/backend/supabase) или [Firebase](/ru/backend/firebase). Приложения в одном project могут использовать общий backend.
  </Accordion>

  <Accordion title="Можно ли использовать свой домен?">
    Да, и если домена ещё нет, его можно купить прямо в Rork. Сначала опубликуйте приложение по адресу `rork.app`, затем см. [Домены](#domains).
  </Accordion>

  <Accordion title="Могут ли два project использовать один адрес?">
    Нет. Адрес принадлежит только одному project. Уже занятый адрес помечается в диалоге как **Connected to another project** — в этом случае выберите поддомен.
  </Accordion>

  <Accordion title="У меня есть проект в Lovable. Придётся создавать его заново?">
    Нет, Rork его импортирует. См. [Из Lovable в мобильное приложение](/ru/import/lovable-to-mobile-app) и держите web app в том же project.
  </Accordion>
</AccordionGroup>
