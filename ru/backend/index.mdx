---
title: "Нужен ли вашему приложению бэкенд?"
---

Разберитесь, когда проекту в Rork действительно нужна настройка бэкенда, а когда без него можно спокойно обойтись. Это руководство поможет не тратить время на бэкенд без необходимости.

<div id="after-building-your-app-in-rork-use-this-documentation-to-decide-if-your-app-needs-a-backend-or-can-stay-local-only">
  ### После создания приложения в Rork воспользуйтесь этой документацией, чтобы понять, нужен ли вашему приложению backend или оно может работать полностью локально.
</div>

<div id="summary">
  ## **Кратко**
</div>

Rork создаёт **фронтенд** вашего приложения: экраны, которые люди видят и с которыми взаимодействуют, — на iPhone, Android и в вебе. **Backend** — это та часть, которую они никогда не видят. Он хранит данные, ведёт учётные записи и следит за соблюдением правил. Нужен он далеко не каждому приложению.

Прочитав эту страницу, вы поймёте, к какой категории относится ваша идея и что делать дальше.

**Что понадобится:**

* Project в Rork
* Общее представление о том, что делает ваше приложение

***

<div id="1-what-counts-as-no-backend">
  ## **1. Что считается «без backend».**
</div>

<div id="local-only-apps-everything-stays-on-the-device">
  ### Полностью локальные приложения (всё остаётся на устройстве)
</div>

Это приложения, которые хранят все свои данные на телефоне пользователя.
Синхронизация не нужна. Вход в аккаунт не требуется. Обмен данными не предусмотрен.

**Примеры:**

* Списки дел
* Приложения для заметок
* Дневники
* Трекеры привычек
* Дневники настроения
* Калькуляторы
* Таймеры
* Конвертеры единиц измерения
* Офлайн-карточки для запоминания
* Фотофильтры / генерация с ИИ
* Виджеты-утилиты

Rork может создать все эти приложения и хранить их данные **вообще без backend**, используя собственное хранилище устройства: локальное хранилище на телефоне и защищённое хранилище для конфиденциальных данных.

Пока данные не покидают устройство, локального хранилища достаточно. Если ваше приложение пока не сохраняет данные, напишите в чате:

```
Убедитесь, что данные хранятся на устройстве и сохраняются после перезапуска
```

***

<div id="tools-with-temporary-non-persistent-data">
  ### Инструменты с временными / несохраняемыми данными
</div>

Таким приложениям долговременное хранение состояния попросту не нужно.

**Примеры:**

* Приложения-песочницы (рисование, эксперименты)
* Локальные мини-игры
* Разовые ИИ-генераторы, которые не сохраняют результат
* Развлекательные инструменты, которые что-то создают, но не должны это запоминать

Если после закрытия приложения ничего сохранять не нужно, то и backend для хранения или обработки данных не требуется. Большинство простых приложений, созданных на Rork, по умолчанию работают именно так.

***

<div id="ai-apps-that-only-call-an-external-api">
  ### ИИ-приложения, которые лишь обращаются к внешнему API
</div>

Если ваше приложение просто отправляет промпт в GPT и возвращает ответ:

**Backend вам не нужен.**

Вы всего лишь отправляете запросы в OpenAI или к другому ИИ-провайдеру.

Backend становится опциональным только тогда, когда:

* Вам нужна история пользователя
* Вам нужна персонализация
* Вам нужно отслеживать использование

То же самое относится к любому внешнему API. Пока вам не нужно хранить эти данные, вы можете спокойно использовать любой API без backend.

***

<div id="2-apps-that-always-need-a-backend">
  ## **2. Приложения, которым backend нужен всегда**
</div>

<div id="apps-with-accounts-or-login">
  ### Приложения с аккаунтами или входом
</div>

Если у пользователя «есть аккаунт», вам понадобятся:

* Аутентификация
* Восстановление данных пользователя
* Синхронизация между устройствами

**Примеры:**

* Социальные приложения
* Приложения для продуктивности с облачной синхронизацией
* Финансовые приложения
* Любые сценарии работы на нескольких устройствах

***

<div id="apps-that-sync-across-devices">
  ### Приложения с синхронизацией между устройствами
</div>

Пользователь пишет заметку на телефоне и рассчитывает увидеть её на ноутбуке.
Для этого нужны:

* База данных
* Облачная синхронизация
* Постоянное хранилище

Без backend здесь не обойтись.

***

<div id="apps-with-sharing-collaboration-or-multiplayer">
  ### Приложения с общим доступом, совместной работой или многопользовательским режимом
</div>

Если один и тот же контент могут видеть, редактировать или комментировать несколько человек:

* Обмен сообщениями
* Списки друзей
* Комментарии
* Публикации
* Социальные ленты
* Совместная работа в реальном времени
* Подбор пар, как в приложениях для знакомств

Всему этому нужен backend.

***

<div id="apps-that-store-files">
  ### Приложения, которые хранят файлы
</div>

Если ваше приложение работает с:

* изображениями
* видео
* PDF-файлами
* аудиозаписями

…и эти файлы должны быть доступны на разных устройствах, вам нужен backend.

Локального хранилища здесь не хватит: оно не подходит для контента, который синхронизируется между устройствами или которым делятся с другими.

***

<div id="apps-with-security-or-access-rules">
  ### Приложения с правилами безопасности или доступа
</div>

Если приложение устанавливает какие-либо правила взаимодействия между пользователями:

* Блокировка
* Модерация
* Ограничение частоты запросов
* Защита от спама

Приложения, работающие только на клиенте, не способны обеспечить соблюдение правил. Здесь понадобится backend.

***

<div id="3-gray-zone-apps-optional-backend">
  ## **3. Приложения «серой зоны» (backend опционально)**
</div>

<div id="local-first-apps-with-optional-sync-later">
  ### Приложения с локальным хранением и возможностью добавить синхронизацию позже
</div>

Некоторые приложения отлично работают без бэкенда, а облачные функции можно добавить позже.

**Примеры:**

* Дневник → добавляем резервное копирование в облако
* Приложение для заметок → добавляем синхронизацию между устройствами
* Офлайн-редактор фотографий → добавляем «поделиться через облако».

Вы можете выпустить первую версию без бэкенда, а синхронизацию добавить по мере роста.

***

<div id="ai-apps-with-memory-or-personalization">
  ### ИИ-приложения с памятью или персонализацией
</div>

Здесь есть выбор:

* **Память только на устройстве** → backend не нужен
* **Облачная память на всех устройствах** → нужен backend
* **Персонализированные модели** → нужен backend

Первая версия может быть простой, с локальным хранилищем; когда появятся пользователи, вы сможете перейти на более безопасную и продвинутую систему — например, облачную или персонализированную.
