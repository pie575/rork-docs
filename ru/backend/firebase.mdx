---
title: "Как подключить backend на Firebase к Rork"
---

Это руководство поможет вам создать backend на Firebase для вашего проекта в Rork. Сюда входит аутентификация пользователей, а также собственные схемы базы данных для функций вашего app.

<Warning>
  **Большинству приложений backend не нужен.** Это сложная работа, которая может сломать уже работающий проект. Сначала прочитайте [Нужен ли вашему приложению backend?](/ru/backend/index). Если backend всё же нужен, но заниматься им самостоятельно вы не хотите, [Rork Cloud](/ru/backend/rork-cloud) даст вам базу данных и серверные функции прямо в Rork — без второй учётной записи.
</Warning>

Это руководство поможет вам создать backend с помощью Firebase. К концу вы сможете настроить вход пользователей по электронной почте, подготовить все базы данных, необходимые для полноценной работы вашего app, и реализовать любые функции, которые сделают приложение персонализированным для пользователей.

<div id="create-a-firebase-account">
  ### **Создайте аккаунт Firebase**
</div>

* Перейдите в [Firebase](https://console.firebase.google.com/) и войдите под своим аккаунтом Google. Возможно, придётся ответить на несколько вопросов, прежде чем вы сможете создать свой первый проект. Это займёт всего пару минут.

* **Создайте новый проект Firebase (придумайте название).**
  Разделы с помощником Gemini AI и Analytics пока можно пропустить — их всегда можно добавить позже.

  <Frame>
    <img alt="Консоль Firebase запрашивает название проекта при создании нового проекта" />
  </Frame>

* **Зарегистрируйте приложение.**
  Когда проект Firebase создан, в нём можно зарегистрировать ваше приложение.
  * Вы увидите кнопку «**Add App**», а рядом — набор платформ. Выберите платформу, соответствующую вашему приложению: **iOS** — для приложения на iPhone (Swift), **Android** — для приложения на Android (Kotlin), **Web** — для web app. После этого Firebase выдаст конфигурацию: файл `GoogleService-Info.plist` для iOS, файл `google-services.json` для Android или объект `firebaseConfig` для веба. Передайте эту конфигурацию агенту в чате, и он подключит SDK к вашему приложению. На скриншотах ниже показан вариант **Web**.

    <img alt="Строка Add App в Firebase с кнопками платформ iOS, Android и Web" />

  * Введите псевдоним приложения. Он используется только внутри системы и не будет виден пользователям.

    <img alt="Шаг Register app в Firebase с запросом псевдонима приложения" />

  * Нажмите Register app.

  * Вам покажут вашу конфигурацию. Что делать дальше, смотрите в разделе **Соберите свою конфигурацию**.

<div id="collect-your-config">
  ### Скопируйте конфигурацию
</div>

На этой же странице после регистрации приложения вы увидите конфигурацию и инструкции по подключению SDK. По сути, мы просто попросим редактор проекта Rork добавить их.

<img alt="Экран настройки Firebase SDK с объектом firebaseConfig, который нужно скопировать" />

Скопируйте содержимое второго окна с объектом firebaseConfig и вернитесь в редактор Rork.

**В редакторе Rork введите следующее:**

```
Установи пакет firebase и настрой начальную конфигурацию.
Также настрой Firebase Auth и Firebase Database:
{ВСТАВЬТЕ СЮДА СКОПИРОВАННУЮ ВЫШЕ КОНФИГУРАЦИЮ}
```

<img alt="Чат Rork с конфигурацией Firebase, вставленной в промпт" />

<Note>
  В остальной части руководства мы создадим **VibeVoice** — соцсеть, где общаются только голосом. На скриншотах агент называет этот же проект SPEEK: так он назывался раньше. В вашем проекте останется ваше название.
</Note>

<div id="creating-the-backend-data-schema">
  ## Создание схемы данных для backend
</div>

Если вы никогда этим не занимались, это, пожалуй, будет самая сложная часть всего процесса, но вы можете воспользоваться помощью ИИ (прямо в Rork). Вам нужно определить схему данных, необходимую для работы вашего приложения, а также функции, которые оно должно уметь выполнять.

Как и в случае с SQL, вам всё равно нужно описать, какие объекты требуются вашему приложению, но Firebase вместо таблиц использует NoSQL. Это значит:

* Вы создадите коллекции (аналог таблиц)
* Каждый пользователь или пост будет документом
* Документ содержит поля
* Кроме того, внутри документов можно размещать вложенные подколлекции

**Вы можете попросить Rork следующее:**

> Перечисли все коллекции схемы данных, необходимые для работы нашего приложения. Я буду использовать этот список для создания коллекций Firestore и правил безопасности.

<Frame>
  <img alt="Rork отвечает списком коллекций Firestore и их полей" />
</Frame>

<div id="create-your-first-database">
  ### Создайте свою первую базу данных
</div>

Чтобы хранить информацию в облаке, нужно включить Firestore Database. Нажмите **Firestore Database** на левой панели в вашем проекте Firebase.

Создайте базу данных и выберите регион, ближайший к вашим пользователям. Изменить его потом не получится, а на скорость работы backend он влияет напрямую.

**После этого добавьте правила безопасности, которые предложил Rork. Перейдите на вкладку Rules и вставьте их.**

<Frame>
  <img alt="Вкладка Rules в Firestore Database, куда вставляются правила безопасности" />
</Frame>

Теперь, когда объекты и правила безопасности определены, можно переходить к созданию коллекций Firestore.

В отличие от Supabase, Firebase **не** требует SQL или заранее созданных таблиц. Firestore создаёт коллекции «на лету», когда приложение записывает в них данные. Так что всю работу можно поручить Rork прямо сейчас. Но сначала нужно настроить Auth, чтобы пользователи могли регистрироваться и получать собственный идентификатор.

<div id="set-up-authentication-in-the-firebase-dashboard-eg-emailpassword-oauth-providers">
  ### Настройте аутентификацию в панели Firebase (например, email/пароль, OAuth-провайдеры)
</div>

Прежде чем подключать схему данных к Firestore, нужно убедиться, что пользователи действительно смогут зарегистрироваться и войти. Firebase Authentication — самая простая часть всей настройки backend: здесь не нужны ни базы данных, ни SQL.

<div id="enable-email-password-authentication">
  ### **Включите вход по email и паролю**
</div>

1. В панели Firebase перейдите в раздел **Authentication** и нажмите **Get Started**.
2. Откройте вкладку **Sign-in method**.
3. Включите **Email/Password**.
4. (Необязательно) Отключите подтверждение email, чтобы упростить разработку.
5. (Необязательно) Включите вход через Google, Apple или по номеру телефона, если планируете использовать их позже. Именно эти способы пользователи просят добавить чаще всего.

Firebase сохраняет эти настройки автоматически, так что теперь достаточно просто попросить Rork включить их.

<div id="integrating-auth-into-rork">
  ### Интеграция аутентификации в Rork
</div>

Теперь, когда аутентификация включена, Rork может сгенерировать всю логику входа и регистрации прямо в вашем проекте.

В редакторе Rork отправьте запрос:

```
Пожалуйста, интегрируй Firebase Authentication в этот проект.
Мне нужны регистрация по email и паролю, вход, выход и корректная работа с сессиями.
Используй:
- createUserWithEmailAndPassword
- signInWithEmailAndPassword
- onAuthStateChanged для сессий
После регистрации также создавай документ пользователя в Firestore в коллекции "users".
```

Rork создаст:

* функцию регистрации
* функцию входа
* слушатель состояния аутентификации
* код для создания первоначального документа пользователя в Firestore
* обновления навигации для авторизованных и неавторизованных пользователей

Так ваше приложение получит полностью рабочую систему аутентификации.

<div id="ask-rork-to-apply-your-schema-and-build-your-functions">
  ## Попросите Rork применить вашу схему и создать функции
</div>

Теперь, когда аутентификация работает, а правила безопасности Firebase настроены, остаётся последний шаг — передать Rork схему вашего приложения, чтобы он сгенерировал всю серверную логику, необходимую вашему проекту.

Именно на этом шаге ваш backend обретает *реальные очертания*. Rork создаст:

* структуры коллекций/документов Firestore
* функции create/read/update/delete
* запросы (лента, посты пользователя, списки и т. д.)
* логику вложенных коллекций (комментарии, лайки, подписчики и т. д.)
* вспомогательные функции загрузки в Firebase Storage (если в схеме есть изображения/аудио/видео)
* полностью типизированные вспомогательные функции, которые сможет вызывать ваше приложение

Для этого откройте редактор Rork и отправьте следующее сообщение:

```
Я добавил правила безопасности Firebase.
Пожалуйста, примени к проекту схему, которую ты описал ранее, и сгенерируй все
необходимые для неё вспомогательные функции: создание, чтение, обновление,
удаление, запросы, а также логику подколлекций и загрузки медиафайлов, если она нужна.
```

Rork прочитает вашу схему и создаст всё необходимое для работы backend.
Если какая-то связь или поле окажутся пропущены, просто обновите схему и отправьте запрос заново.

После этого шага ваш app будет полностью связан с Firebase: аутентификация, Firestore и все backend-функции вашего app заработают в полном объёме!

<div id="test-and-make-sure-your-database-updates-with-functions-in-your-app">
  ### Протестируйте и убедитесь, что база данных обновляется функциями вашего приложения
</div>

Теперь, когда всё подключено, вы увидите, как ваши изменения обновляют таблицы базы данных и сохраняются в них! Поздравляем, вы создали backend!
