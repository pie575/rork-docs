title: "Что такое API?"
---

Сторонние API расширяют возможности ваших приложений и позволяют создавать то, что раньше казалось невозможным. В этом документе рассказывается, что такое API, какие из них уже доступны в Rork и как быстро подключить свои собственные.

<div id="so-youve-built-an-awesome-app-on-rork">
  ## Итак, вы создали классное приложение на Rork...
</div>

Но теперь хочется вывести его на новый уровень. Возможно, пользователи просят функцию, для которой нужны более сложные инструменты. Например, фотоприложение, созданное в Rork, может добавить ИИ-фильтры для снимков, а приложение для поиска музыки — определение жанра по записи песни. Что бы вы ни создавали на Rork, это всегда можно доработать и улучшить. В этом и есть сила **внешних API** и нашего передового конструктора приложений в Rork.

<div id="what-is-an-api">
  ### Что такое API?
</div>

Если объяснять максимально просто, API — это **договор**. Договор фиксирует конкретные условия, о которых договорились две стороны. Представьте, что эти стороны — ваше приложение и чужое. Точно так же API говорит: «Если вы передадите мне Данные A из своего приложения, эта компания обязуется вернуть вам Данные B из своих сервисов».

> Например, вы создаёте на Rork приложение, которое помогает находить лучшие рестораны поблизости с учётом ваших предпочтений в еде. Чтобы получить список ресторанов рядом, вам понадобится API вроде Google Maps API. В приложении вы определяете местоположение пользователя (в Rork это делается легко), отправляете эти данные в Google Maps API (как именно — расскажем далее в документации), а в ответ, по условиям договора, получаете список ресторанов.

Разработчики рассчитывают на то, что этот договор не изменится, ведь любые изменения могут сломать их приложение. Именно поэтому у API есть документация и чёткие схемы работы.

<div id="what-is-an-external-or-third-party-api">
  ### Что такое внешний или сторонний API?
</div>

Чтобы ответить на этот вопрос, сначала разберёмся, что такое внутренний API. API — это своего рода договор между двумя сторонами. И она вполне может быть внутренней! Например, когда вы отправляете промпт в Rork, мы обрабатываем его и собираем ваше приложение через внутренний API, который создали на нашем backend. Это внутренний API — третья сторона здесь не нужна.

Сторонний, или внешний, API разрабатывается и поддерживается за пределами Rork. Такие API не обязательно находятся под нашим контролем, но Rork поможет вам подключиться к ним и поддерживать это подключение. Вот несколько примеров сторонних API (список далеко не полный):

<div id="how-to-find-the-right-api-for-your-project">
  ### Как подобрать подходящий API для вашего проекта
</div>

Для генерации изображений, видео, аудио или 3D-моделей с помощью ИИ внешний API вам вообще не нужен: Rork создаёт такие медиафайлы сам, а в разделе [Изображения, видео, аудио и 3D-модели](/ru/features/assets) объясняется, как их запросить. Если вам нужна любая другая функция — читайте дальше.

1. **Определите, что именно должно измениться в приложении**
   Это то единственное изменение, которое вы хотите увидеть в приложении по сравнению с его текущим состоянием. Если вы не можете сформулировать нужное изменение, подобрать API для его реализации будет сложно. Формулируйте просто, иначе на следующем шаге идея может не пройти проверку на осуществимость. Можно посмотреть на это и с другой стороны: какие источники данных у вас уже есть (местоположение пользователей, их предпочтения в еде, сделанные ими фотографии и т. д.) и что вы хотите с этими данными делать.

2. **Проверьте осуществимость**
   В ChatGPT, Gemini или любой другой LLM с веб-поиском можно искать API с помощью такого запроса:

   > Я создаю мобильное приложение. Оно (кратко опишите своё мобильное приложение). Сейчас функциональность такая: (опишите текущую функциональность и имеющиеся у вас источники данных). Я хотел бы добавить/изменить (новое изменение, определённое на шаге 1). Пожалуйста, поищи в интернете надёжные и хорошо поддерживаемые API, которые я могу подключить, чтобы это реализовать.

   Так вы поймёте, осуществим ли ваш замысел. Это важная проверка, которую все разработчики делают перед использованием нового API. Иначе есть риск взять решение, которое не подойдёт под ваш сценарий или сломается, потому что его плохо поддерживают.

3. **Зарегистрируйтесь в сервисе этого API, найдите документацию и сгенерируйте учётные данные**
   Большинство API требуют создать аккаунт, а также оформить какие-либо аутентификационные данные. У каждого API это устроено по-своему, но обычно речь об API-ключе и/или каком-то запросе аутентификации. Вручную в этом легко запутаться, поэтому в той же ветке ChatGPT попросите помочь разобраться, какие именно данные вам нужны. Просто дайте ссылку на документацию и спросите:

   > Какие ключи/учётные данные мне нужны для работы с этим API и как их сгенерировать/найти? Они нужны мне, чтобы потом добавить их в моё приложение на Rork. Также, пожалуйста, составь инструкцию по использованию этого API, которую я смогу передать в ИИ-редактор Rork, чтобы внести изменения в моё мобильное приложение.

4. **Теперь вы готовы передать эту информацию в Rork и собрать новую функцию!**
   О том, как передать эту информацию в Rork и реализовать изменения, читайте в следующем разделе.

Теперь, когда вы проделали работу по подбору подходящего API для своего проекта, можно передать всю эту информацию в Rork и реализовать задуманное. Вот лучшие практики для этого:

<div id="how-to-tell-rork-to-use-external-apis">
  ### Как объяснить Rork, что нужно использовать внешние API
</div>

1. Составим простой набор правил, который мы передадим в редактор Rork, чтобы добавить нужную функциональность:
   1. **Мы хотим заменить это (текущая функция приложения) на это (новая функция приложения).**
   2. **Для этого мы будем использовать внешний API (название внешнего API).**
   3. **Вот полная документация по тому, что нам нужно: (скопируйте документацию или вставьте инструкции, которые вы попросили сгенерировать ChatGPT на шаге 3 предыдущей части)**
   4. **Вот мои учётные данные, необходимые для работы с этим API: (вставьте учётные данные, которые вы получили на шаге 3 предыдущей части)**
2. Передайте эти 4 заполненных предложения в редактор Rork. Rork сам определит оптимальный способ добавить API в вашу кодовую базу и приложение.
3. Проверьте внесённые изменения в приложении и доработайте их, если что-то сломалось.
4. **Советы по устранению неполадок:**
   1. Если функция не работает, отправьте текст ошибки в Rork — он сможет её исправить. Если внятной ошибки нет, попросите Rork: **Залогируй вызов API, чтобы мы могли понять, почему он не срабатывает**.
   2. Если функция работает, но полученные данные не такие, как вы ожидали, или чего-то не хватает, попросите Rork: **Залогируй данные, возвращаемые вызовом API, чтобы мы могли правильно использовать их в нашем приложении**
5. Поздравляем! Вы только что повысили ценность своего приложения и подключили внешний API! Расскажите нам о том, что вы создаёте, в нашем Discord *(ссылка в левом верхнем углу документации)*. Нам будет очень интересно узнать, как вы используете внешние API!
