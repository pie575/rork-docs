---
title: "Перенос приложения между iOS, Android и вебом"
---

Превратите Android-приложение в iOS-приложение с помощью ИИ (или наоборот), преобразуйте кодовую базу React Native в нативный код на Swift и Kotlin и выпускайте приложения сразу для всех платформ из одного проекта Rork.

<video />

Проект Rork не привязан к одной платформе. Один проект может содержать **нативное приложение для iOS (Swift)**, **нативное приложение для Android (Kotlin)** и **веб-приложение**. У каждого приложения свой код, но они могут использовать общий чат и общий backend. Поэтому «перенести приложение на другую платформу» — это функция, а не переписывание с нуля.

<div id="convert-an-android-app-to-ios-with-ai">
  ## Как превратить Android-приложение в iOS-приложение (с помощью ИИ)
</div>

У вас есть Android-приложение (в Rork или импортированное из репозитория) и вы хотите запустить его на iPhone?

1. Если приложения ещё нет в Rork, сначала [импортируйте его репозиторий](/ru/import/import-from-github) вместе с исходным кодом на Kotlin/Java. Агент прочитает его, даже если новое iOS-приложение будет написано на Swift.
2. В проекте напишите в чате:

```
Create an iOS version of this app
```

3. Подтвердите виджет **&quot;Add iOS app?&quot;**. Агент пересоберёт экраны с нативным интерфейсом iOS, сохранив тот же backend, модель данных и бизнес-правила.
4. Проверьте результат в облачном симуляторе iOS, а затем [опубликуйте приложение в App Store](/ru/store-guides/publish-app-store).

<div id="ios-app-native-android-app">
  ## iOS-приложение → нативное Android-приложение
</div>

Обратный путь. В своём iOS-проекте нажмите **+** (Add preview platform) → **Android (Kotlin)** или попросите об этом в чате:

<Frame>
  <img alt="Меню добавления платформы: Android (Kotlin) и Web" />
</Frame>

Rork создаст нативное приложение на Kotlin в том же проекте. Публикация: [создайте файл AAB для Google Play](/ru/submitting-to-play-store/creating-the-aab-file).

<div id="react-native-expo-codebase-native-app">
  ## Кодовая база React Native / Expo → нативное приложение
</div>

Уже есть кодовая база React Native или Expo (из Bolt, от подрядчика или ваша собственная)? Rork пересоберёт её в нативный код.

1. Залейте её на GitHub, если её там ещё нет.
2. Импортируйте: **GitHub to Mobile App** на [rork.com](https://rork.com) → вставьте URL репозитория → **Generate app now**.

<Frame>
  <img alt="Диалог импорта из GitHub" />
</Frame>

Агент читает ваш исходный код на JavaScript или TypeScript и заново собирает экраны, навигацию, потоки данных и дизайн в виде **нативного приложения для iPhone (Swift)**, **нативного приложения для Android (Kotlin)** или **веб-приложения** — что выберете. Сам продукт остаётся прежним, меняется только код интерфейса: он становится Swift, Kotlin или React.

Дальше публикация идёт через Rork: встроенный процесс Publish берёт на себя сборку и отправку в App Store или Google Play, так что настраивать что-либо самостоятельно не нужно.

<Info>
  Не знаете, какую платформу выбрать? См. [iPhone, Android или веб: в чём разница](/ru/swift-vs-react-native/whats-the-difference).
</Info>

<div id="mobile-app-web-app">
  ## Мобильное приложение → веб-приложение
</div>

Для любого мобильного проекта можно сделать веб-версию: **Project Settings → Add new app → Web** — или просто попросите:

```
Добавь веб-версию этого приложения
```

веб-приложение публикуется по адресу `your-app.rork.app` из меню **Publish** (позже можно подключить собственный домен). Отлично подходит для лендингов, админ-панелей или десктопной версии-компаньона.

<div id="every-combination-at-a-glance">
  ## Все комбинации одним взглядом
</div>

| Из \ В                                                | iOS (Swift)               | Android (Kotlin)          | Web                      |
| ----------------------------------------------------- | ------------------------- | ------------------------- | ------------------------ |
| **iOS (Swift)**                                       | —                         | Добавить платформу / чат  | Добавить платформу / чат |
| **Android (Kotlin)**                                  | Добавить платформу / чат  | —                         | Добавить платформу / чат |
| **Web (вкл. импортированные сайты и конструкторы)**   | Добавить платформу / чат  | Добавить платформу / чат  | —                        |
| **React Native / Expo (импортированный репозиторий)** | агент пересоберёт нативно | агент пересоберёт нативно | Добавить платформу / чат |

«Добавить платформу / чат» = нажмите **+** в заголовке проекта, откройте **Project Settings → Add new app** или просто попросите агента.

<div id="faq">
  ## Часто задаваемые вопросы
</div>

<div id="is-the-conversion-a-literal-code-translation">
  ### Является ли конвертация дословным переводом кода?
</div>

Нет, и это к лучшему. Агент заново собирает интерфейс из нативных компонентов каждой платформы, сохраняя продукт неизменным: те же экраны, те же сценарии, те же данные. В итоге вы получаете приложения, которые ощущаются естественно на каждой платформе, а не порт «по наименьшему общему знаменателю».

<div id="do-the-platforms-stay-in-sync-afterwards">
  ### Останутся ли платформы синхронизированными в дальнейшем?
</div>

У них общий проект, общий backend и общий чат. Запрашивая новую функцию, укажите агенту, к каким приложениям она относится («добавь тёмную тему и в iOS, и в Android»), — и он обновит каждую нативную кодовую базу.

<div id="can-i-have-different-features-per-platform">
  ### Могут ли функции отличаться на разных платформах?
</div>

Да. Часто функции для выездных сотрудников оставляют только в мобильном приложении, а панель администратора выносят в веб-приложение.
