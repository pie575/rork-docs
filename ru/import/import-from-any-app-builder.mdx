---
title: "Перенос проекта из любого конструктора приложений в Rork"
---

Перенесите проект из Bolt, v0, Replit, FlutterFlow, Bubble, Glide, Softr или Base44 в Rork и получите нативное мобильное приложение: экспортируйте код в GitHub, а затем импортируйте его. Включая шаги экспорта для каждого конструктора.

Собрали что-то в другом ИИ-конструкторе или no-code-инструменте и хотите получить настоящее нативное мобильное приложение? Порядок действий почти всегда один и тот же:

1. **Перенесите проект в репозиторий GitHub** (у каждого серьёзного конструктора есть экспорт или синхронизация).
2. **Импортируйте этот репозиторий в Rork** с помощью [импорта из GitHub](/ru/import/import-from-github).
3. Rork читает ваши настоящие исходные файлы и пересобирает продукт как нативное приложение для iOS / Android.

Если ваш исходный инструмент вообще не позволяет экспортировать код (у некоторых no-code-инструментов такой возможности нет), переходите к разделу [Нет экспорта кода?](#no-code-export-import-it-anyway) — перенести проект всё равно можно.

<div id="step-1-export-your-project-to-github">
  ## Шаг 1. Экспортируйте проект в GitHub
</div>

Как выгрузить репозиторий из каждого популярного конструктора:

<div id="lovable">
  ### Lovable
</div>

В Lovable есть полноценная синхронизация с GitHub, а в Rork — импорт в один клик специально для него. Воспользуйтесь отдельным руководством: [Превратите приложение Lovable в мобильное приложение](/ru/import/lovable-to-mobile-app).

<div id="bolt-boltnew">
  ### Bolt (bolt.new)
</div>

Bolt может отправить ваш проект в GitHub: откройте проект → панель инструментов → **Connect to GitHub** (либо **Export → Download**, чтобы скачать ZIP-архив и загрузить его самостоятельно). Bolt создаёт стандартные веб-проекты, а если вы запрашивали мобильное приложение — проекты на React Native. Rork импортирует любой из них и пересобирает в нативное приложение.

<div id="v0-by-vercel">
  ### v0 by Vercel
</div>

Проекты v0 уже хранятся в Git, если вы их запушили: используйте **Add to codebase / Download ZIP** либо подключите проект v0 к Git-репозиторию в Vercel. Затем импортируйте полученный репозиторий в Rork.

<div id="replit">
  ### Replit
</div>

В вашем Repl: **Git pane → Connect to GitHub → Create repository**, затем сделайте push. Приложения Replit Agent под капотом — это обычный исходный код, поэтому импортируются без проблем.

<div id="flutterflow">
  ### FlutterFlow
</div>

**Settings → Integrations → GitHub → Connect** экспортирует сгенерированный код Flutter (на платных тарифах); также можно воспользоваться кнопкой **Download Code**. Rork не собирает приложения на Flutter — вместо этого агент разбирает ваши экраны, логику и структуру данных по коду на Dart и пересобирает приложение нативно. Укажите в промпте, что исходный проект — на Flutter.

<div id="softr-glide-bubble-no-code-export">
  ### Softr / Glide / Bubble (без экспорта кода)
</div>

Эти платформы не позволяют выгрузить пригодный для работы исходный код. См. раздел [Нет экспорта кода?](#no-code-export-import-it-anyway) ниже.

<div id="base44-other-ai-builders">
  ### Base44 / другие ИИ-конструкторы
</div>

Большинство ИИ-конструкторов (Base44, Create, Databutton и им подобные) поддерживают синхронизацию с GitHub или скачивание кода. Найдите пункт **GitHub / Export code** в настройках проекта, получите репозиторий и импортируйте его.

<Tip>
  Если у вас есть только ZIP-архив: создайте пустой репозиторий на GitHub, распакуйте архив локально и выполните команды ниже в распакованной папке. Замените URL на адрес своего репозитория. Этого достаточно, чтобы Rork смог выполнить импорт.

  ```
  git init
  git add .
  git commit -m "Initial import"
  git branch -M main
  git remote add origin https://github.com/YOUR-NAME/YOUR-REPO.git
  git push -u origin main
  ```
</Tip>

<div id="step-2-import-the-repository-into-rork">
  ## Шаг 2. Импортируйте репозиторий в Rork
</div>

1. Перейдите на [rork.com](https://rork.com) и нажмите **GitHub to Mobile App** под полем промпта.
2. Вставьте URL репозитория.
3. Нажмите **Generate app now** или **I have extra requests**, чтобы описать, что нужно изменить в ходе миграции (это отличный момент, чтобы запросить навигацию в нативном стиле или отказаться от ненужных функций).

  <img alt="Диалог импорта из GitHub на rork.com" />

Агент настраивает синхронизацию с GitHub, анализирует исходный код (экраны, маршруты, модели данных, интеграции, переменные окружения) и пересобирает приложение как нативное:

<div id="step-3-reconnect-your-backend">
  ## Шаг 3. Переподключите backend
</div>

Слой данных обычно переносится как есть:

* **Supabase / Firebase**: передайте агенту URL вашего project и публичные клиентские ключи в виде переменных окружения — и мобильное приложение будет работать с той же базой данных и аутентификацией, что и раньше. Для Supabase используйте публикуемый ключ (прежнее название — `anon`) и не отключайте Row Level Security. Для Firebase используйте публичную клиентскую конфигурацию. См. [Supabase](/ru/backend/supabase) и [Firebase](/ru/backend/firebase).
* **Собственный API**: агент считывает вызовы API из импортированного исходного кода и использует те же эндпоинты.
* **Backend ещё нет**: попросите агента настроить его на [Rork Cloud](/ru/backend/rork-cloud).

<Warning>
  Никогда не размещайте в приложении секретный ключ Supabase (прежнее название — `service_role`) или любой приватный ключ API. Ключи внутри опубликованного мобильного приложения может прочитать кто угодно. Храните приватные ключи на стороне сервера — в [Rork Cloud](/ru/backend/rork-cloud) или в Supabase Edge Function.
</Warning>

<div id="no-code-export-import-it-anyway">
  ## Нет экспорта кода? Переносите всё равно
</div>

Если ваш текущий инструмент (Softr, Glide, Bubble, Adalo и подобные) не отдаёт исходный код, миграция всё равно возможна. Просто начните не с кода, а с самого продукта:

1. Сделайте **скриншоты всех экранов** существующего приложения и приложите их к первому промпту в Rork.
2. Добавьте **публичную ссылку** на приложение, чтобы агент мог изучить пользовательские сценарии.
3. Опишите модель данных простыми словами («пользователи, заказы, у каждого заказа есть позиции...»).
4. Если ваши данные хранятся в Airtable / Google Sheets / Supabase, скажите об этом агенту — он сможет подключиться к тому же источнику данных или импортировать данные.

Вы удивитесь, насколько точным получается результат первой генерации, когда у агента есть реальные скриншоты.

<div id="why-not-just-wrap-my-existing-app-in-a-webview">
  ## Почему бы просто не обернуть существующее приложение в webview?
</div>

Сервисы-обёртки помещают ваш сайт внутрь нативной оболочки. Работает это ровно до первого сбоя: Apple регулярно отклоняет такие пустые обёртки (Guideline 4.2, Minimum Functionality), push-уведомления и офлайн-режим работают ненадёжно, а приложение так и не ощущается нативным. Rork пересобирает интерфейс нативно, сохраняя ваш продукт и данные, — именно этого и ждут магазины приложений.

<div id="faq">
  ## Частые вопросы
</div>

<div id="which-builders-does-rork-import-from-best">
  ### Из каких конструкторов Rork импортирует лучше всего?
</div>

Из всех, которые отдают реальный исходный код: Lovable, Bolt, v0, Replit, проекты Cursor, приложения, написанные вручную. С FlutterFlow работает вариант с чтением кода. Для Softr/Glide/Bubble понадобится подход со скриншотами.

<div id="will-everything-be-migrated-11">
  ### Всё ли переносится один в один?
</div>

Агент сохраняет ваш продукт: экраны, сценарии, брендинг и модель данных. Попиксельное совпадение — не цель: нативные мобильные паттерны (панели вкладок, нативные жесты, push-уведомления) обычно делают приложение лучше, чем прямая копия.

<div id="can-i-keep-the-old-web-app-running">
  ### Можно ли оставить старое веб-приложение работать?
</div>

Да. Импорт никак не затрагивает ваш исходный проект. Многие разработчики какое-то время используют старое веб-приложение и новое мобильное приложение на Rork параллельно, на одном backend, а объединяют их позже.
