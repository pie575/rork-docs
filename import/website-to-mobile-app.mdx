You have a website (a store, a booking page, a SaaS, a community) and you want it on your customers' home screens as a real app. Rork builds a native iOS and Android app for your existing site: native navigation and screens, powered by the same content and backend you already run.

## Pick your path

| Your situation | Best path |
| --- | --- |
| The site's code is on GitHub (or you can export it) | Import the repository |
| Built with Lovable | [Lovable import](/import/lovable-to-mobile-app) |
| Built with another builder (Bolt, v0, Replit, FlutterFlow) | [Import from any app builder](/import/import-from-any-app-builder) |
| No access to the code (Wix, Squarespace, WordPress, agency site) | Describe and attach screenshots |
| You already have a Rork web app | Add iOS/Android to the project |

## Path A: Import the website code

If your website's source is available, import gives the agent the most to work with:

<Steps>
  <Step title="Click GitHub to Mobile App">
    On [rork.com](https://rork.com), click **GitHub to Mobile App** and paste the repository URL.
  </Step>
  <Step title="Add extra instructions">
    Press **I have extra requests** to tell the agent what the mobile app should focus on:

    ```text
    Make a customer app for browsing and booking; skip the admin pages.
    ```
  </Step>
  <Step title="Review the result">
    The agent inspects the source, keeps your branding and data flows, and builds native mobile screens. Keep iterating in chat.
  </Step>
</Steps>

## Path B: No code access

No repository? Give the agent the product instead:

<Steps>
  <Step title="Start a new project">
    On [rork.com](https://rork.com), create a new project.
  </Step>
  <Step title="Paste your URL and attach screenshots">
    Paste your website URL in the prompt, attach screenshots of the key pages (home, product page, checkout, profile), and describe what the app should do:

    ```text
    Make an iOS app for my salon website https://example.com.
    Customers should browse services, pick a stylist, book a time slot,
    and get a reminder push notification before the appointment.
    ```
  </Step>
  <Step title="Iterate in chat">
    The agent designs a native app around your site's content and connects to your existing systems where possible.
  </Step>
</Steps>

## Add iOS and Android apps to an existing Rork project

Every Rork project can hold multiple apps that share one project and backend. If you already have a web app in Rork, adding native mobile is quick.

**Option 1: The + button.** In the project header, click **\+** (Add preview platform) and choose the platform.

**Option 2: Project Settings.** Open **Project Settings → Add new app** → pick Android or iOS.

**Option 3: Just ask in chat.**

```text
Add an Android version of this app
```

## Why native instead of a webview wrapper?

Website-to-app converter services wrap your URL in a webview. That is fast, but:

- **App Store risk.** Apple's Guideline 4.2 (Minimum Functionality) regularly rejects apps that are "just a website".
- **No real native features.** Camera metadata, offline mode, background tasks, widgets, and push notifications need native code.
- **It never feels right.** Browser scrolling, no native gestures, no home-screen quality polish.

A Rork app is compiled native code with native UI.

## FAQ

<AccordionGroup>
  <Accordion title="Does this work with WordPress, Shopify, Wix, or Squarespace?">
    Yes, use Path B (describe and attach screenshots). These platforms do not expose app-ready source code. For stores, tell the agent which checkout to keep.
  </Accordion>

  <Accordion title="Website-to-app converters give me an APK in minutes. Why is this different?">
    Those converters wrap your URL in a webview shell. Rork builds real native screens. It takes longer, and the result feels like an actual app. Native screens also help you meet Apple's Guideline 4.2, which is where webview wrappers usually fail.
  </Accordion>

  <Accordion title="Can I convert my website to an app for free?">
    You can start for free: the Free plan runs Design mode. To build the working app and preview it in the simulator, you need a paid plan. Publishing to the App Store and Google Play also needs the stores' own developer accounts.
  </Accordion>
</AccordionGroup>
