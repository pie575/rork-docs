Built something in another AI builder or no-code tool and want it as a real native mobile app? The recipe is almost always the same: export your code to GitHub, import that repository into Rork, and the agent rebuilds the product natively.

## Step 1: Export your project to GitHub

How to get a repository out of each popular builder:

**Bolt (bolt.new):** Open your project, go to the toolbar, and click **Connect to GitHub**. Or use **Export → Download** as a ZIP and push it yourself. Bolt generates standard web projects that Rork imports and rebuilds natively.

**v0 by Vercel:** Use **Add to codebase / Download ZIP**, or connect your v0 project to a Vercel Git repository. Import the resulting repo into Rork.

**Replit:** In your Repl, go to **Git pane → Connect to GitHub → Create repository**, then push. Replit Agent apps are normal source code underneath.

**FlutterFlow:** Go to **Settings → Integrations → GitHub → Connect** (paid plans) to export your generated Flutter code. Rork reads the Dart source and rebuilds the app natively. Mention in your prompt that the source is Flutter.

**Lovable:** Lovable has a dedicated one-click import. See [Convert your Lovable app to a mobile app](/import/lovable-to-mobile-app).

**Base44 and other AI builders:** Most AI-first builders (Base44, Create, Databutton) offer GitHub sync or a code download. Find it in your project settings.

<Tip>
  If you only have a ZIP: create an empty repository on GitHub, unzip it locally, then push it.

  ```bash
  git init
  git add .
  git commit -m "Initial import"
  git branch -M main
  git remote add origin https://github.com/YOUR-NAME/YOUR-REPO.git
  git push -u origin main
  ```
</Tip>

## Step 2: Import the repository into Rork

1. Go to [rork.com](https://rork.com) and click **GitHub to Mobile App** under the prompt box.
2. Paste the repository URL.
3. Click **Generate app now**, or **I have extra requests** to describe what you want changed during the migration (a great moment to ask for native-first navigation, or to drop features you no longer need).

The agent audits your source (screens, routes, data models, integrations, env vars), and rebuilds the app natively.

## Step 3: Reconnect your backend

Your data layer usually survives the migration as-is:

- **Supabase / Firebase:** Give the agent your project URL and your public client keys as environment variables. The mobile app talks to the same database and auth as before.
- **Custom API:** The agent reads your API calls from the imported source and reuses the same endpoints.
- **No backend yet:** Ask the agent to set one up with [Rork Cloud](/backend/rork-cloud).

<Warning>
  Never put a Supabase `service_role` key or any private API key in the app. Anyone can read the keys inside a shipped mobile app. Keep private keys on the server side, in Rork Cloud or a Supabase Edge Function.
</Warning>

## No code export? Import it anyway

If your current tool (Softr, Glide, Bubble, Adalo) will not give you source code, you can still migrate:

1. Take **screenshots of every screen** and attach them to your first prompt in Rork.
2. Add the **public URL** of the app.
3. Describe the data model in plain words ("users, orders, each order has line items...").
4. If your data lives in Airtable or Google Sheets, tell the agent; it can connect to the same data source.

## FAQ

<AccordionGroup>
  <Accordion title="Which builders does Rork import from best?">
    Anything that exports real source code: Lovable, Bolt, v0, Replit, Cursor projects, and hand-written apps. FlutterFlow works via code reading. Softr, Glide, and Bubble require the screenshot approach.
  </Accordion>

  <Accordion title="Will everything be migrated 1:1?">
    The agent preserves your product: screens, flows, branding, and data model. Pixel-perfect parity is not the goal. Native mobile patterns (tab bars, native gestures, push notifications) usually make the app better than a straight copy.
  </Accordion>

  <Accordion title="Can I keep the old web app running?">
    Yes. Importing does not touch your original project. Many builders run the old web app and the new Rork mobile app side by side on the same backend, then consolidate later.
  </Accordion>

  <Accordion title="Why not just wrap my existing app in a webview?">
    Wrapper services put your website inside a native shell. Apple regularly rejects thin wrappers under Guideline 4.2 (Minimum Functionality), push notifications and offline are unreliable, and the app never feels native. Rork rebuilds the UI natively while preserving your product and data.
  </Accordion>
</AccordionGroup>
