title: "Convert your app between iOS, Android, and web"

Convert an Android app to iOS with AI (or the reverse), turn a React Native codebase into native Swift and Kotlin, and ship every platform from one Rork project.

<video />

A Rork project isn't locked to one platform. One project can contain a **native iOS app (Swift)**, a **native Android app (Kotlin)**, and a **web app**. Each app has its own code. They can share one chat and one backend. That makes "convert my app to another platform" a feature, not a rewrite from scratch.

## Convert an Android app to iOS (with AI)

Have an Android app (in Rork, or imported from a repository) and want it on iPhone?

1. If the app isn't in Rork yet, [import its repository](/import/import-from-github) first, Kotlin/Java source included. The agent reads it even though the new iOS app will be Swift.
2. In the project, ask in chat:

```
Create an iOS version of this app
```

3. Confirm the **"Add iOS app?"** widget. The agent rebuilds the screens with native iOS UI, reusing the same backend, data model, and business rules.
4. Preview it in the iOS cloud simulator, then [publish to the App Store](/store-guides/publish-app-store).

## iOS app → native Android app

The mirror path. In your iOS project, click **+** (Add preview platform) → **Android (Kotlin)**, or ask in chat:

## React Native / Expo codebase → native app

Already have a React Native or Expo codebase (from Bolt, a contractor, or your own work)? Rork rebuilds it as native code.

1. Push it to GitHub if it isn't there already.
2. Import it: **GitHub to Mobile App** on [rork.com](https://rork.com) → paste the repo URL → **Generate app now**.

<Frame>
  <img alt="The GitHub import dialog" />
</Frame>

The agent reads your JavaScript or TypeScript source, then rebuilds the screens, navigation, data flows, and design as a **native iPhone app (Swift)**, a **native Android app (Kotlin)**, or a **web app**, whichever you pick. Your product stays the same. The UI code becomes Swift, Kotlin, or React.

From there, publishing runs through Rork: the built-in Publish flow handles the build and the App Store or Google Play submission, so there is nothing to configure yourself.

<Info>
  Not sure which platform to pick? See [iPhone, Android, or web: what's the difference](/swift-vs-react-native/whats-the-difference).
</Info>

## Mobile app → web app

Any mobile project can grow a web version: **Project Settings → Add new app → Web**, or ask:

```
Add a web version of this app
```

The web app publishes to a `your-app.rork.app` URL from the **Publish** menu (you can attach a custom domain later). Great for landing pages, admin panels, or a desktop companion.

## Every combination at a glance

| From \ To                                 | iOS (Swift)                | Android (Kotlin)           | Web                 |
| ----------------------------------------- | -------------------------- | -------------------------- | ------------------- |
| **iOS (Swift)**                           | n/a                        | Add platform / chat        | Add platform / chat |
| **Android (Kotlin)**                      | Add platform / chat        | n/a                        | Add platform / chat |
| **Web (incl. imported sites & builders)** | Add platform / chat        | Add platform / chat        | n/a                 |
| **React Native / Expo (imported repo)**   | agent rebuilds it natively | agent rebuilds it natively | Add platform / chat |

"Add platform / chat" = click **+** in the project header, use **Project Settings → Add new app**, or just ask the agent.

## FAQ

### Is the conversion a literal code translation?

No, and that's a good thing. The agent rebuilds the UI with each platform's native components while keeping your product identical: same screens, same flows, same data. You get apps that feel right on each platform instead of a lowest-common-denominator port.

### Do the platforms stay in sync afterwards?

They share the project, the backend, and the chat. When you ask for a feature, tell the agent which apps it applies to ("add dark mode to both iOS and Android") and it updates each native codebase.

### Can I have different features per platform?

Yes. It's common to keep the field-crew features mobile-only and add an admin dashboard as the web app.
