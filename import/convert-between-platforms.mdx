A Rork project is not locked to one platform. One project can contain a native iOS app (Swift), a native Android app (Kotlin), and a web app. Each app has its own code. They can share one chat and one backend. That makes "convert my app to another platform" a feature, not a rewrite from scratch.

## Every combination at a glance

| From | To iOS (Swift) | To Android (Kotlin) | To Web |
| --- | --- | --- | --- |
| **iOS (Swift)** | n/a | Add platform / chat | Add platform / chat |
| **Android (Kotlin)** | Add platform / chat | n/a | Add platform / chat |
| **Web** | Add platform / chat | Add platform / chat | n/a |
| **React Native / Expo (imported repo)** | Agent rebuilds it natively | Agent rebuilds it natively | Add platform / chat |

"Add platform / chat" means: click **\+** in the project header, use **Project Settings → Add new app**, or just ask the agent.

## Three ways to add a platform

**Option 1: The + button.** In the project header, click **\+** (Add preview platform) and choose the platform to add.

**Option 2: Project Settings.** Open **Project Settings → Add new app** and pick iOS, Android, or Web.

**Option 3: Ask in chat.**

```text
Add an Android version of this app
```

The agent shows an **Add Android app?** confirmation, then builds the native Kotlin app reusing your project's logic and backend.

## Convert an Android app to iOS

1. If the app is not in Rork yet, import its repository first (Kotlin/Java source included).
2. In the project, ask in chat:

```text
Create an iOS version of this app
```

3. Confirm the widget. The agent rebuilds the screens with native iOS UI, reusing the same backend, data model, and business rules.
4. Preview it in the iOS cloud simulator, then [publish to the App Store](/store-guides/publish-app-store).

## Convert an iOS app to Android

In your iOS project, click **\+** → **Android (Kotlin)**, or ask in chat:

```text
Add an Android version of this app
```

Rork builds a native Kotlin app in the same project. To publish, see [create the AAB for Google Play](/submitting-to-play-store/creating-the-aab-file).

## React Native / Expo to native app

1. Push the repo to GitHub if it is not there already.
2. On [rork.com](https://rork.com), click **GitHub to Mobile App** → paste the repo URL → **Generate app now**.

The agent reads your JavaScript or TypeScript source, then rebuilds the screens, navigation, data flows, and design as a native iPhone app (Swift), a native Android app (Kotlin), or a web app.

## Mobile app to web app

Any mobile project can grow a web version:

```text
Add a web version of this app
```

The web app publishes to a `your-app.rork.app` URL from the **Publish** menu. You can attach a custom domain later.

## Per-app settings

Each app in the project has its own icon, home screen name, and bundle identifier / package name. Configure them in **Project Settings** before publishing.

## Publishing each platform

- **iOS:** [Publish to the App Store](/store-guides/publish-app-store) directly from Rork.
- **Android:** [Generate the AAB and upload to Google Play](/submitting-to-play-store/creating-the-aab-file).
- **Web:** One click in the project's **Publish** menu.

## FAQ

<AccordionGroup>
  <Accordion title="Is the conversion a literal code translation?">
    No, and that is a good thing. The agent rebuilds the UI with each platform's native components while keeping your product identical: same screens, same flows, same data. You get apps that feel right on each platform instead of a lowest-common-denominator port.
  </Accordion>

  <Accordion title="Do the platforms stay in sync afterwards?">
    They share the project, the backend, and the chat. When you ask for a feature, tell the agent which apps it applies to ("add dark mode to both iOS and Android") and it updates each native codebase.
  </Accordion>

  <Accordion title="Can I have different features per platform?">
    Yes. It is common to keep field-crew features mobile-only and add an admin dashboard as the web app.
  </Accordion>
</AccordionGroup>
