Lovable is great at shipping web apps, but it produces a website, not a native mobile app. If you want your Lovable project on the App Store or Google Play, Rork can import it directly and rebuild it as a real native mobile app (not a webview wrapper), while staying connected to your Lovable project's source code.

<Info>
  Rork rebuilds your app with native UI. This is different from wrapper tools (Capacitor, Median, and similar) that put your website inside a webview. Those often get rejected under Apple's Guideline 4.2 (Minimum Functionality) because they do not offer a native experience.
</Info>

## Before you start

1. **Connect your Lovable project to GitHub** (inside Lovable: Settings → GitHub → Connect). Lovable pushes your project code to a repository on your GitHub account. Rork needs that repository.
2. Have your Lovable app URL ready. It looks like `https://your-app.lovable.app`.

## Step-by-step

<Steps>
  <Step title="Click Lovable to Mobile App">
    On [rork.com](https://rork.com), under the prompt box, click the **Lovable to Mobile App** button.
  </Step>
  <Step title="Paste your Lovable app URL">
    A dialog opens. Paste your `https://your-app.lovable.app` link.

    Click **Generate app now** to start immediately, or **I have extra requests** to add instructions first (for example: "keep the branding but redesign the navigation as native tabs").
  </Step>
  <Step title="Link the GitHub repository (Lovable Sync)">
    In the new project's chat, the agent asks you to set up **Lovable Sync**:

    1. Paste the URL of the GitHub repository that Lovable created for your project.
    2. If you have not installed the Rork GitHub App yet, click **Install GitHub app** and grant it access to that repository.
    3. Click **Link repo**.

    Once connected, Rork clones your Lovable source into the project and uses it as the source of truth for screens, logic, and data models.

    Eligible Lovable projects unlock **free migration credits**. If your repository qualifies, you will see this right in the flow.
  </Step>
  <Step title="Environment variables come along automatically">
    Right after the repo is linked, Rork scans your source for environment variables. Public client keys that are committed in the Lovable source (Supabase anon key, Firebase web config, Stripe publishable key) are imported automatically. If anything is missing, an in-chat panel asks you for the values.
  </Step>
  <Step title="Watch the mobile app come to life">
    The agent surveys your screens, flows, copy, colors, and assets, then rebuilds the product as a native mobile app with native tab bars and navigation stacks. Marketing and landing pages typically become onboarding material rather than in-app screens.

    You will see the app running in the cloud simulator as it is built. Keep iterating by chatting.
  </Step>
</Steps>

## What about my Supabase backend?

If your Lovable app uses Supabase, the imported source includes your Supabase client code and schema references. The committed anon key is picked up by the env scan, so your web app and mobile app share the same database and auth out of the box.

## FAQ

<AccordionGroup>
  <Accordion title="Can Lovable itself make a native mobile app?">
    No. Lovable outputs React and Vite web applications. You can pin them to a home screen as a PWA, but that is still a website: no App Store distribution and limited offline support.
  </Accordion>

  <Accordion title="Does this convert Lovable to React Native?">
    No, and that is the point. Rork rebuilds your app as native code: Swift for iPhone, Kotlin for Android. The agent rebuilds the UI natively instead of porting web code line by line.
  </Accordion>

  <Accordion title="Can I export my Lovable code without GitHub?">
    Lovable Sync goes through GitHub. If you only have a ZIP of your code, push it to a new GitHub repository and use the regular GitHub import instead.
  </Accordion>

  <Accordion title="My Lovable repo isn't recognized">
    Lovable Sync checks that the repository was generated by Lovable (recent commits from the Lovable bot). Make sure you linked the repo that Lovable manages, not a manual copy.
  </Accordion>

  <Accordion title="Do I need to keep paying for Lovable after migrating?">
    That is up to you. Many builders keep Lovable for their web app and use Rork for mobile. A Rork project can also hold a web app next to the mobile apps, so you can consolidate everything into Rork.
  </Accordion>
</AccordionGroup>
