---
title: Share and Clone a Project
description: Get a project in front of someone else, or spin off an independent copy to try a new direction.
---

Two actions cover most of what you'll want to do with a project you don't want to keep entirely to yourself: **sharing** it with another person, and **cloning** it into a separate copy. This page walks through both quickly — for the full breakdown of collaborator roles and permissions, see [Share a Project](/collaborate/share-a-project).

## Share a project

<Steps>
  <Step title="Open the invite panel">
    In the project header, click the invite button next to **Publish**.
  </Step>
  <Step title="Pick email or link">
    Either enter the person's email and choose a role for them, then press **Invite** — or press **Create** under "Create invite link" to generate a shareable URL instead.
  </Step>
  <Step title="Send it over">
    An email invite expires after 7 days; a link stays valid for a year. Send whichever fits how you're reaching the person.
  </Step>
  <Step title="Wait for them to sign in">
    The recipient needs a Rork account. Once they sign in using the invite, they land directly inside your project.
  </Step>
</Steps>

<Tip>
  An invite link works like a password — anyone who has it can join the project. Prefer email invites when you want to control exactly who gets access.
</Tip>

## Clone a project

Cloning gives you a completely independent copy of a project — useful for testing a risky change, branching into a new feature direction, or handing someone a starting point without giving them access to the original.

<Steps>
  <Step title="Open the project menu">
    Click the **⋯** menu in the project header.
  </Step>
  <Step title="Choose Clone project">
    Select **Clone project** from the menu.
  </Step>
  <Step title="Name the copy">
    Give the new project a name in the dialog that appears.
  </Step>
  <Step title="Confirm">
    Press **Clone Project**. Rork opens the copy in a fresh chat, ready to diverge from the original.
  </Step>
</Steps>

A clone carries over the code, the full chat history, and any generated assets — images, video, audio, or 3D models — from the moment you cloned it. Environment variables come along too, except for keys that Rork generates and manages itself, which get refreshed for the new project.

<Note>
  A clone is a snapshot, not a live link back to the original. Once it's created, changes on either side stay independent of the other, and the clone belongs to whoever created it — not necessarily the owner of the source project.
</Note>

One thing that doesn't carry over: if the original project is published, its live web address stays with the original. The clone starts unpublished, even if you publish it later to a different address.
