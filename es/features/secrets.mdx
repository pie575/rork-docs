---
title: "Claves de API y variables de entorno"
---

Guarda las claves de API en tu proyecto de Rork en lugar de pegarlas en el código. En esta página se explica el editor de Secrets, qué variables llegan al teléfono y cómo mantener en privado una clave privada.

La mayoría de las apps útiles necesitan alguna clave: una API del clima, un servicio de envío de correos, una pasarela de pagos, un proveedor de modelos. Esas claves van en los **Secrets** de tu proyecto, no en el código ni en un mensaje del chat.

<div id="where-secrets-live">
  ## Dónde se guardan los secrets
</div>

Abre **More → Secrets** en un proyecto.

<Frame>
  <img alt="El panel de Secrets de Rork con una fila RESEND_API_KEY, un valor oculto, una etiqueta Server-side only, un botón Add Variable y los botones Bulk Edit y Save" />
</Frame>

<Steps>
  <Step title="Pulsa Add Variable">
    Aparece una fila nueva con un campo **Key** y un campo **Value**.
  </Step>

  <Step title="Escribe el nombre en mayúsculas y con guiones bajos">
    `RESEND_API_KEY`, `STRIPE_SECRET_KEY`, `OPENWEATHER_API_KEY`. Usa el nombre exacto que indica la documentación del proveedor.
  </Step>

  <Step title="Pega el valor">
    Rork lo oculta al instante. El botón del ojo lo muestra cuando necesites comprobarlo.
  </Step>

  <Step title="Pulsa Save">
    Rork guarda la variable y vuelve a compilar las partes de tu app que la necesitan.
  </Step>
</Steps>

Para añadir varias de golpe, es más rápido usar **Bulk Edit**. Pega una variable por línea con el formato `KEY=value`.

<div id="how-far-a-variable-travels">
  ## Hasta dónde llega una variable
</div>

La etiqueta que aparece debajo de cada clave es lo más importante de esta página: te dice quién puede leer ese valor.

| Etiqueta                               | Adónde va el valor                                                 |
| -------------------------------------- | ------------------------------------------------------------------ |
| **Solo del lado del servidor**         | Se queda en el servidor. Tus usuarios nunca podrán leerlo          |
| **Disponible en tiempo de build**      | Queda incorporada en la app al compilarla                          |
| **Disponible para todos los usuarios** | Se envía dentro de la app y puede leerla cualquiera que la instale |

Lo que determina esto es el nombre. Una variable cuyo nombre empieza por `EXPO_PUBLIC_` se envía a la propia app; todo lo demás se queda en el servidor. El editor repite la regla al final: &quot;Prefix with `EXPO_PUBLIC_` to make a variable available on the client-side&quot;.

<Warning>
  Nunca le pongas un nombre con `EXPO_PUBLIC_` a una clave secreta, ni la pegues en el código de tu app. Todo lo que se envía dentro de una app se puede extraer de ella, lo que se traduce en una clave filtrada de tu cuenta, usada por desconocidos y facturada a ti. Una clave privada va en una variable **Solo del lado del servidor**, utilizada por una función de servidor.
</Warning>

Dos ejemplos dejan clara la diferencia:

* `EXPO_PUBLIC_SUPABASE_URL` no supone ningún problema como valor público: es una dirección y está protegida por las reglas de la base de datos.
* `STRIPE_SECRET_KEY` debe ser **Solo del lado del servidor**. Puede mover dinero.

Si tu funcionalidad necesita una clave privada, pídele a Rork una función de servidor y la creará:

```
Envía el correo de confirmación desde una función de servidor para que la clave de Resend se mantenga privada
```

Algunas filas están marcadas como **Gestionado por Rork** o **Gestionado por la integración de Supabase**. Rork se encarga de escribirlas y rotarlas, así que no las toques.

<div id="when-rork-asks-you-for-a-key">
  ## Cuando Rork te pide una clave
</div>

Por lo general no hace falta abrir el editor de Secrets. Cuando un build necesita una clave, Rork se detiene y te la pide en el chat, con un campo por clave y una breve descripción de para qué sirve cada una. Pega los valores y pulsa **Save &amp; Continue**: el build seguirá desde donde se quedó.

Cuando Rork ya conoce los valores, por ejemplo tras una integración, la tarjeta solo te pide confirmarlos: **Yes, set them**.

<div id="who-can-see-your-keys">
  ## Quién puede ver tus claves
</div>

| Rol    | Secrets                     |
| ------ | ---------------------------- |
| Owner  | Puede leer y editar          |
| Editor | Puede leer y editar          |
| Viewer | Ve el panel, no puede editar |

Es decir, un editor de tu proyecto puede leer tus claves. Ten esto en cuenta a la hora de invitar editores. Consulta [Compartir un proyecto y trabajar en equipo](/es/collaborate/share-a-project).

Un proyecto clonado conserva tus variables, salvo las claves que gestiona el propio Rork, que se generan de nuevo para la copia.

<div id="rotate-a-key-you-leaked">
  ## Rotar una clave que filtraste
</div>

Si una clave acaba en algún sitio público, no basta con cambiarla en Rork. Hazlo en este orden:

<Steps>
  <Step title="Revoca la clave en el proveedor">
    Elimínala o rótala en el panel del propio proveedor. Eso es lo que realmente hace que la clave deje de funcionar.
  </Step>

  <Step title="Crea una clave nueva">
    Copia el nuevo valor.
  </Step>

  <Step title="Actualiza la variable en Rork">
    Mismo nombre de clave, nuevo valor y luego **Save**.
  </Step>

  <Step title="Revisa dónde quedó expuesta">
    Si estaba en tu código, pídele a Rork que la elimine y que lea el valor desde la variable en su lugar.
  </Step>
</Steps>

<div id="faq">
  ## Preguntas frecuentes
</div>

<AccordionGroup>
  <Accordion title="¿Debería pegar mi clave de API en el chat?">
    Es mejor usar el editor de Secrets o la tarjeta que muestra Rork cuando necesita una clave. En ambos casos el valor queda fuera de la conversación.
  </Accordion>

  <Accordion title="¿Los secretos llegan a GitHub?">
    No. Se guardan en el proyecto, no en tu código, así que no se incluyen en los commits. Vuelve a configurarlos en cualquier entorno donde ejecutes el código por tu cuenta. Consulta [Cómo sincronizar tu proyecto con GitHub](/es/tutorials/how-to-connect-github).
  </Accordion>

  <Accordion title="¿Los secretos son por proyecto o por cuenta?">
    Por proyecto. Un proyecto con una app de iPhone y una app web comparte un mismo conjunto de variables.
  </Accordion>

  <Accordion title="Agregué una variable y la app sigue sin verla.">
    Primero recarga la vista previa. Si es una app nativa, el valor se incorpora durante el build, así que hace falta un build nuevo. Si al nombre le falta el prefijo `EXPO_PUBLIC_`, la app no puede leerlo por diseño, y esa llamada le corresponde al servidor.
  </Accordion>

  <Accordion title="¿Necesito mi propia clave de OpenAI para usar IA en mi app?">
    No necesariamente. Rork Cloud le da modelos a tu app sin que necesites claves propias de un proveedor. Consulta [Qué es Rork Cloud](/es/backend/rork-cloud).
  </Accordion>

  <Accordion title="¿Dónde van las claves de Supabase?">
    Al conectar Supabase se configuran solas y quedan marcadas como gestionadas. Consulta [Cómo agregar un backend de Supabase a Rork](/es/backend/supabase).
  </Accordion>
</AccordionGroup>
